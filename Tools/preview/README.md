# App Store 미리 보기 영상 (2026-10-12)

| 파일 | App Store Connect 칸 | 크기 |
|---|---|---|
| `out/app-preview-886x1920.mp4` | 아이폰 15.5 · 15.9cm (6.1 · 6.3") | 886×1920, 28.6초 |
| `out/app-preview-1200x1600.mp4` | 아이패드 32.8 · 33.0cm (12.9 · 13") | 1200×1600, 29.1초 |

H.264 30fps, 무음 트랙. 크기는 2026-10-12 사용자가 보낸 App Store Connect 화면 기준.
애플 규정(심사 지침 2.3.4)대로 **앱 화면을 녹화한 것만** 쓰고 위에 자막 띠만 얹었다. 화면은 체험 자료(가상의 가족)다.

| 장면 | 길이 | 자막 |
|---|---|---|
| 점검 입력 — 숫자를 적자 지난주 대비 증감이 뜬다 | 6.2초 | 매주 토요일, 직접 적기 |
| 점검 완료 — 연속 기록 · 구성원별 | 4.0초 | 점검 완료, 연속 기록 |
| 현황판 — 로드맵 · 총자산으로 스크롤 | 7.0초 | 계획선 위인가, 아래인가 |
| 시뮬레이션 — 월 적립 손잡이를 끌자 2049년 예상이 바뀐다 | 8.0초 | ‘만약에’를 돌려 보기 |
| 자산 진단 — 스크롤 | 4.8초 | 원칙은 앱이 기억합니다 |

아이패드는 같은 장면 · 자막에 길이만 다르다(6 · 4 · 7.5 · 8 · 5초). **점검 장면은 치지 않고 화면만 보여 준다** —
아이패드 시뮬레이터에서 점검 칸을 누르면 점검 창이 15초쯤 뒤 저절로 닫혀 뒤 장면을 찍지 못했다(네 번째 녹화).
`-startReview` 로 바로 열면 창이 열렸다 닫혔다를 되풀이했다(세 번째). 실제 아이패드에서도 그런지는 확인 전이다.

## 만드는 법

1. **녹화** — `Actions → App Store 미리 보기 녹화`(`.github/workflows/preview.yml`)를 손으로 돌린다. 맥 러너가
   UI 테스트 대본(`AppUITests/PreviewRecording.swift`)으로 앱을 눌러 가며 시뮬레이터를 녹화하고 `raw/raw.mp4` 로 커밋한다.
2. **편집** — `node Tools/preview/edit.mjs` (아이패드는 `--device ipad`, 녹화도 워크플로에서 `device: ipad`). 녹화에서 고른 구간(파일 안의 `SCENES`)을 잘라 886×1920 · 자막으로 잇는다.

**구간은 눈으로 고르고, 자를 때는 처음부터 풀어 `trim` 으로 자른다.** 녹화가 가변 프레임이라 입력 앞 `-ss` 로 감으면 0.6초쯤 밀려 점검 장면 끝에 홈 화면이 4프레임 비쳤다(10-12, 사용자가 찾음). 대본이 남기는 장면 표시(`raw/marks.txt`)는 녹화 시간축과 어긋난다 — `simctl recordVideo` 는
화면이 멈춘 동안 프레임을 건너뛰어, 뒤로 갈수록 수십 초씩 차이가 났다. 새로 녹화하면 프레임을 훑어 `SCENES` 의
`from` · `to` 를 다시 잡는다. 지금 것은 두 녹화에서 잘 찍힌 장면만 모았다(`raw.mp4` = 세 번째, `raw-run2.mp4` = 두 번째).

녹화에서 겪은 것: CI 에는 LLDB 가 없어 스킴에서 디버거를 꺼야 앱이 뜬다(`debugEnabled: false`). CI 에서는 `typeText`
가 키보드를 1분 가까이 기다린 뒤 친다 — 그 구간은 1.4배로 줄였다.

## 올리기

App Store Connect → 다음 버전 페이지 → 미리 보기 및 스크린샷 → 아이폰 **15.9cm** 칸에 886×1920, 아이패드 **33.0cm** 칸에 1200×1600 을 끌어 놓는다.
**미리 보기는 새 버전을 낼 때만 바꿀 수 있다.** 올린 뒤 **포스터 프레임**(정지 화면)을 고른다 — 시뮬레이션의 87억 장면이 좋다.
