# 참고 — 기존 1페이지 계획서 구조 분석

사용자가 이미 운영 중인 A4 1페이지 계획서(`우리 가족 노후자금 준비`)를 분해해
앱이 반드시 표현할 수 있어야 하는 요소를 정리했습니다.
**이 문서의 모든 숫자는 구조 설명을 위한 예시로 치환한 값입니다.**
실제 금액·기관명 등 개인 금융 정보는 저장소에 커밋하지 않습니다.

> 이 1페이지는 요구사항의 원본입니다. 새 기능을 넣을지 판단할 때
> "이 1페이지를 더 잘 만들어 주는가?"를 기준으로 삼습니다.

## 구성 블록

### A. 헤더
- 문서 제목, 계획 시작일(`2023.11.27 ~`), 계획 기간(`2023–2049`)
- **기준 시점 라벨** — `2026.08 기준 · 이사 후 자산`
  → 같은 자산을 두 번 세지 않기 위한 "어느 상태 기준인가" 선언. 앱에도 필요.

### B. 전체 자산 로드맵 (가로 타임라인)
연도별 마일스톤. 각 항목은 다음을 가진다.

| 필드 | 예시 |
|---|---|
| 연도 | 2035 |
| 가장(家長) 나이 | 51세 |
| 예상 총자산 | 15.3억 |
| 라벨 | "복리가 스스로 굴러간다" |
| 상태 | 과거 / 현재 / 미래 |

라벨이 금액보다 중요하다. `수익 > 적립금`, `수익 > 연봉`, `일하지 않아도 되는 시점`처럼
**의미 있는 교차점**이 동기 부여의 핵심이다. 일부는 계산으로 자동 판정할 수 있다.

### C. 구성원 카드 (4인)
각 카드의 구성:
1. **헤더** — 이름/역할, 나이, 특성 배지(예: 세적), 현재 합계 금액
2. **보유 종목 표** — 종목명 · 상태 태그 · 금액
   - 상태 태그가 중요: `동결`(신규 자금 투입 안 함), `적립 25만`, `신규`, `정리 완료`
3. **매월 적립** — 총액, 본인 부담/회사 매칭 구분, 배분 상세 한 줄
4. **주석(※)** — 그 구성원에게만 적용되는 규칙·한도·재검토 시점
5. **성장 궤적 미니 바차트** — 7개 시점의 예상 금액 (2026/2029/2031/2035/2038/2041/2049),
   자녀 카드는 그 시점의 **자녀 나이**를 함께 표기

### D. 운용 원칙 (6개)
번호 + 한 줄 제목 + 부연 설명. 점검 주기(분기 1회) 표기.
상당수가 **계산으로 위반 여부를 판정할 수 있다**:

| 원칙 | 자동 점검 |
|---|---|
| 동결 종목에는 신규 자금 0원 | 가능 — 해당 종목 매수 거래 감지 |
| 개별주 4% · 특정 ETF 5% 상한 | 가능 — 비중 계산 |
| 자녀 계좌 국내 50 / 미국 50, 국내 상한 60% | 가능 — 지역 비중 계산 |
| 비상금 2,000만원은 투자하지 않는다 | 가능 — 현금성 자산 하한 |
| 하락장에도 멈추지 않는다 | 불가 — 텍스트로만 표시 |
| 소득이 오르면 금액만 올린다 | 불가 — 텍스트로만 표시 |

### E. 목돈 흐름 (보증금 흐름)
미래 특정 시점의 큰 자금 이동. `2억 → 1억(이사 후) + 1억(투자 전환)` 형태.
**예측에 직접 들어가는 입력**이며, 중복 계산 방지를 위해 기준 시점 선언과 함께 다뤄야 한다.
퇴직금 유입, 주택 구입 유출도 같은 성격.

### F. 가족 요약 표
- 투자자산 합계 / 비투자 자산(보증금) / 총자산
- 매월 적립 합계, 그중 본인 부담
- 국가(지역) 비중 — `한국 29.8 / 미국 70.2`

### G. 유의 사항 (세금·규제·한도 노트)
가장 길고, 가장 자주 갱신되는 영역. 성격별로 나뉜다.

| 성격 | 예시 | 앱에서의 형태 |
|---|---|---|
| 제약 규칙 | 미국 세적자는 한국 상장 ETF(PFIC) 금지 | **입력 시 자동 경고** |
| 연간 한도 | 연금저축 합산 600만, ISA 총 1억 | **한도 대비 사용량 게이지** |
| 기한 있는 할 일 | 증여 신고 2026년 내, Form 8621 제출 | **기한 있는 체크리스트 + 알림** |
| 예정된 점검 | 다음 점검 2027.03, ISA 만기 2027.09.07 | **일정 + 알림** |
| 상태 메모 | 연금보험 환급률 89.2% — 정상 | **자유 메모** |

### H. 푸터
- 한 줄 선언문 (`계획은 끝났다. 이제는 시간이 일한다.`)
- 다음 점검일, 임박한 만기, 진행 중인 목돈 배치 기간

## 여기서 도출되는 설계 요구사항

1. **구성원이 1급 개체다.** 자산·적립·연금·궤적이 모두 구성원 단위로 쪼개지고 가구로 합산된다.
2. **보유 자산에 "상태"가 있다.** 동결/적립/신규/정리 — 단순 수량·금액만으로는 부족하다.
3. **월 적립액은 계좌·종목 단위로 배분되고, 본인 부담과 회사 매칭이 구분된다.**
4. **원칙은 데이터다.** 텍스트로만 두지 말고 점검 가능한 것은 규칙으로 등록해 자동 검사한다.
5. **세적(tax residency)이 상품 선택을 제약한다.** 미국 세적 구성원에게 한국 상장 ETF를 넣으려 하면 막아야 한다.
6. **목돈 이벤트와 기준 시점이 예측의 정확도를 좌우한다.** 중복 계산 방지가 실제로 겪는 문제다.
7. **유의사항 중 기한이 있는 것은 알림이 되어야 한다.** 종이 문서가 못 하는 일이 바로 이것이다.
8. **마일스톤 라벨은 사용자가 쓴다.** 금액만으로는 동기가 생기지 않는다.
9. **이 1페이지 자체를 앱에서 다시 뽑을 수 있어야 한다.** PDF/이미지 내보내기와 공유는 부가 기능이 아니다.

## 종이 문서 대비 앱이 주는 것

| 종이의 한계 | 앱의 답 |
|---|---|
| 만든 순간부터 낡는다 | 매주 직접 적어 넣는 순간 궤적이 다시 그려진다 (시세는 가져오지 않는다 — ADR-0005) |
| "만약에"를 못 해본다 | What-if 슬라이더로 즉시 재계산 |
| 실제 궤적과 계획을 못 겹쳐 본다 | 매일 스냅샷 → 계획선 대비 실제선 |
| 원칙 위반을 사람이 찾아야 한다 | 규칙 자동 점검 |
| 기한을 놓친다 | 알림 |
| 갱신하려면 다시 만들어야 한다 | 입력 → 1페이지 자동 재생성 |
