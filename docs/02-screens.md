# 2. 화면 설계 (IA)

## 2.1 탭 구조

```
┌──────────┬──────────┬──────────┬──────────┬──────────┐
│  현황판  │   자산   │   계획   │ 시뮬레이션│  더보기  │
│ chart.bar│ list.bul │ calendar │  slider  │ ellipsis │
└──────────┴──────────┴──────────┴──────────┴──────────┘
```

| 탭 | 목적 | 사용 빈도 |
|---|---|---|
| **현황판** | 1페이지 계획서의 재현. 보는 화면. | 매일~매주 |
| **자산** | 계속 입력하는 화면. 구성원 → 계좌 → 종목. | 매주 토요일 |
| **계획** | 적립·연금·목돈·마일스톤·가정. 바뀌면 고치는 화면. | 분기 1회 |
| **시뮬레이션** | What-if 슬라이더와 시나리오 비교. | 월 1회 |
| **더보기** | 원칙, 유의사항/할 일, 내보내기, 설정. | 주간 점검 시 |

> 다섯 탭은 iOS 상한입니다. 사용 데이터를 보고 "시뮬레이션"을 현황판 안으로
> 접어 넣는 4탭 구성으로 줄일 수 있게, 각 탭은 독립 화면으로 만듭니다.

## 2.2 현황판 (Home)

세로 스크롤 하나. 위에서부터 **사실 → 계획 → 경고 → 구성원 → 합계** 순서.

### 2.2.0 이번 주 점검 바
헤더 바로 아래, 궤적보다 위. **루틴으로 되돌리는 자리**다.

- 미입력: `이번 주 점검 · 토요일까지 D-2` + `12주 연속 기록 중` + **[지금 입력]**
- 완료: `이번 주 점검 완료 · 03.13` + `+931만 · 계획 대비 +1.0%`
- 밀림: `2주째 밀림` — 색을 바꿔 경고로 승격

### 2.2.1 헤더 (고정, 스크롤 시 축소)
- 제목: 사용자가 정하는 계획 이름 (기본 "우리 가족 노후자금 준비")
- **기준 시점 배지** — 예: `2026.08 기준 · 이사 후` (탭하면 기준 시점 편집)
- **가구 총자산** — 화면에서 가장 큰 숫자
- 전월 대비 증감(금액 + %), 계획선 대비 편차
- 금액 가리기 토글(눈 아이콘)

### 2.2.2 로드맵 타임라인 (가로 스크롤)
1페이지 상단의 그 타임라인. 마일스톤 칩이 나열되고 **오늘**이 강조된다.

```
 ●────────◉────────○────────○────────○
2023     2026     2031     2041     2049
39세     42세     47세     57세     65세
 —      3.0억    9.7억    28.3억   59.1억
시작    ·지금·   수익>연봉 일하지    목표
                          않아도
```

- 과거 마일스톤: 실제 스냅샷 값(회색 채움)
- 미래 마일스톤: 예측 중앙값(윤곽선)
- 칩을 탭하면 그 시점의 구성원별 분해와 근거(적립 누계 / 수익 / 목돈 유입)를 시트로 표시
- 자동 판정 마일스톤(`연간 수익 > 연간 적립금`, `연간 수익 > 연봉`, `자산 > 목표`)은
  계산되어 자동으로 꽂히고, 사용자 라벨과 함께 표시된다

### 2.2.3 순자산 궤적 차트 (핵심)
Swift Charts. 하나의 X축(시간), 하나의 Y축(금액).

| 요소 | 표현 |
|---|---|
| 과거 실제 | 진한 실선 + 데이터 포인트 |
| 오늘 | 세로 기준선 + 라벨 |
| 예측 중앙값 | 점선 |
| 신뢰구간(10~90%) | 반투명 밴드 |
| 계획선(초기 계획) | 얇은 회색 실선 — 계획 대비 실제를 겹쳐 본다 |
| 은퇴 시점 | 세로 기준선 |
| 목표 금액 | 가로 기준선 |

- 기간 토글: `1년 / 3년 / 전체 / 은퇴까지`
- 표시 토글: `명목 / 실질(오늘 돈 기준)`
- 스크럽(길게 눌러 이동)하면 해당 시점의 금액·구성원 분해를 표시
- 차트 아래 **한 줄 요약**: "이대로 가면 65세에 59.1억 · 목표의 100% · 92세까지 유지"

### 2.2.4 경고 스트립
있을 때만 나타난다. 없으면 이 영역이 사라지는 것이 정상 상태다.

- 🔴 **원칙 위반** — "개별주 비중 4.6% · 상한 4% 초과" → 탭하면 해당 종목으로
- 🟠 **세적 제약** — "딸 계좌에 한국 상장 ETF 보유 (PFIC)"
- 🟡 **한도 임박** — "연금저축 납입 578만 / 600만 (96%)"
- ⏰ **기한 임박** — "증여 신고 2026.12.31 · 117일 남음"
- 🔵 **입력 유도** — "엄마의 연금 정보를 넣으면 예측이 정확해집니다"

### 2.2.5 구성원 카드
1페이지의 4개 카드. 세로로 쌓거나(iPhone) 2열 그리드(가로/iPad).

```
┌────────────────────────────────┐
│ 아빠  본인 · 42세      2.5억   │
│ ────────────────────────────── │
│ VOO                 5,085만    │
│ QQQM                2,804만    │
│ SCHD  · 동결        2,410만    │
│ … 외 4건                       │
│ ────────────────────────────── │
│ 매월 적립  261만 (본인 243만)  │
│ ▁▂▃▄▅▆█  2.5억 → 36.8억        │  ← 미니 성장 궤적
└────────────────────────────────┘
```

- 상위 4~5개 종목만 보여주고 나머지는 접는다
- 상태 태그(`동결`/`적립 25만`/`신규`)를 종목 옆에 배지로
- 하단 미니 바차트는 1페이지의 성장 궤적 그대로. 자녀는 그 시점 나이를 함께 표기
- 탭 → 구성원 상세

### 2.2.6 가구 요약
- 투자자산 / 비투자 자산(보증금·현금) / 총자산
- 매월 적립 합계, 그중 본인 부담
- 지역 비중 바 (`한국 29.8 · 미국 70.2`), 자산군 도넛, 통화 비중

### 2.2.7 푸터
- 사용자가 쓰는 한 줄 선언문 (편집 가능)
- 다음 점검일 / 임박한 만기
- **[1페이지 내보내기]** 버튼

## 2.3 자산 탭 — "계속 입력하는" 화면

### 2.3.1 목록
구성원 → 계좌 → 보유 자산 3단 트리. 섹션 헤더에 소계.
검색, 정렬(금액순/이름순/자산군), 필터(이번 주 미입력·상태·자산군·통화·구성원).

각 행: `종목명 · 상태 배지 · 평가액 · 지난 점검 대비 증감`
하단 고정 **[주간 점검 시작 · N건]**.

### 2.3.2 주간 점검 (핵심 UX)
**이 앱의 심장.** 자산 24건을 3분 안에 끝내는 것이 설계 목표다.

- 진입 경로: 토요일 알림 탭 / 현황판의 [지금 입력] / 자산 탭 하단 버튼
- **전 종목을 한 목록에 늘어놓고 위에서 아래로 훑는다.** 사용자가 스프레드시트에서
  한 주를 한 행씩 채우던 방식 그대로다. 어디까지 했는지, 앞뒤 값이 어떤지가 항상 보인다.
  (한 번에 한 종목씩 보여주는 방식도 만들어 봤으나, 진행 상황과 맥락이 사라져서 버렸다)
- 구성원별로 그룹핑하고 그룹 헤더에 `6 / 10` 진행률. 헤더는 스크롤 시 상단에 고정
- 각 행이 곧 숫자 입력 필드. 키패드가 뜬 채로 유지되고
  키보드 위 도구막대의 **[다음]** 으로 아래 행으로 이동 (`FocusState` 체이닝).
  숫자 키패드에는 return 키가 없으므로 이 도구막대가 유일한 이동 수단이다
- 모든 행에 **지난주 값**을, 활성 행에는 **증감(금액·%)** 을 표시 → 오타를 즉시 알아챈다
- 포커스가 옮겨가면 그 행이 화면 가운데로 스크롤된다
- 값을 안 바꾸고 넘어가면 **변동 없음**으로 기록
- 입력 주기 태그로 대상을 줄인다: `매주` / `월 1회`(해지환급금 등) / `고정`(보증금 — 자동 건너뜀)
- 상단 진행 바 + 하단 `7 / 24` — 남은 양이 항상 보인다
- 마지막 행에서 **[완료]** → 스냅샷 1건 저장 → **점검 완료 화면**

### 2.3.3 토요일 알림
- 기본 매주 토요일 오전 9시(시각 변경 가능). 미입력 시 일요일 같은 시각 1회 재알림
- 배너: `이번 주 점검 — 24건` / `지난주 대비 얼마나 늘었는지 지금 기록하세요` / `12주 연속 기록 중`
- 길게 눌러 확장하면 **총액 빠른 입력** — 전체 목록을 열지 않고 가족 총자산 하나만 적는다
  - 액션: `다음 주에` / `총액만 기록` / `전체 입력`
  - 총액만 기록하면 궤적의 점 하나는 남고 구성원·종목별 분해는 비어 있는 채로 표시된다.
    다음 점검 때 채우면 그 주로 소급 배분한다.
- 알림에 금액을 노출하지 않는 옵션(잠금 화면 프라이버시)

### 2.3.4 점검 완료 화면 (입력의 보상)
입력이 끝나자마자 뜬다. **여기서 계획 대비 실적을 체감한다.**

- 이번 주 변화 큰 숫자 (`+931만원`)
- 3열 비교: `계획 3억 890만` / `실제 3억 1,204만` / `차이 +314만`
- 최근 12주 실적선 대 계획선 미니 차트
- **연속 기록 주차** — 채워진 사각형이 늘어난다
- 구성원별 증감
- 원칙 점검 결과 요약 (`6개 중 5개 준수`)
- 다음 점검일 안내

### 2.3.5 보유 자산 상세/편집
- 기본: 종목명, 심볼, 자산군, 상장 국가, 통화, 소속 계좌, 상태 태그
- 평가 방식 선택: **① 평가액 직접 입력**(기본) / **② 수량 × 직접 입력 단가**
- 입력 주기: `매주` / `월 1회` / `고정`
- 적립 설정: 월 적립 금액(적립 계획과 연결)
- 메모 (1페이지의 ※ 주석)
- 거래 내역 (선택) — 없어도 앱이 완전히 동작한다
- 저장 시 **규칙 검사** 실행 → 위반이면 저장은 하되 경고 배너를 남긴다 (막지 않는다)

### 2.3.6 계좌 편집
소유자, 기관, 계좌 종류, 통화, 부채 여부, 연간 납입 한도(있으면 게이지 표시).

## 2.4 계획 탭

섹션 목록 하나.

1. **구성원** — 생년월, 세적, 은퇴 목표 나이, 기대수명 가정
2. **적립 계획** — 구성원별 월 금액과 배분
   ```
   아빠 · 월 261만 4천
     ├ 일반계좌 100만   VOO 44 / QQQM 32 / SCHD 24
     ├ 연금저축 15만
     ├ ISA 85만
     ├ IRP 25만
     └ 연금보험 36.1만  본인 18.1 + 회사 매칭 18.0
   ```
   - 연 증가율(연봉 상승률), 시작·종료 시점
   - **회사 매칭은 별도 필드** — 합계와 본인 부담을 각각 보여준다
3. **미래 소득(연금)** — 종류, 수령 시작 나이, 월 금액, 물가연동, 수령 기간
4. **목돈 이벤트** — 날짜, 금액, 방향, 라벨, 배치 대상 계좌
   ```
   2026.12  전세보증금 전환   2억 → 1억   +1억 투자 전환
   2027.03  퇴직금 유입       +7,000만    일반계좌
   ```
   - 중복 계산 방지를 위해 **기준 시점**과 함께 표시하고, 기준 시점 이전 이벤트는 회색 처리
5. **마일스톤** — 연도 + 라벨 + (자동 판정 여부)
6. **가정** — 자산군별 기대수익률·변동성, 인플레이션율, 은퇴 후 목표 생활비
7. **목표** — 은퇴 목표 금액 또는 은퇴 후 월 생활비 기준

## 2.5 시뮬레이션 탭

계획 탭이 **가정을 정하는 곳**이라면 시뮬레이션 탭은 **가정을 흔들어 보는 곳**입니다.
손잡이를 돌려도 저장되지 않습니다. `[계획에 반영]`을 눌러야 계획으로 넘어갑니다.
이 분리가 없으면 무심코 돌린 슬라이더가 계획을 덮어씁니다.

위에서 아래로:

1. **헤드라인** — `2049년 예상` + 큰 금액 + `계획보다 8억 2,000만원 많다` + 오늘 돈 환산
2. **밴드 카드**
   - 신뢰구간(하위 10%~상위 10%) 면 + 예상선(실선) + 목표선
   - **계획 그대로(점선)는 손잡이를 돌렸을 때만 그립니다.** 손잡이가 기본값이면
     계획선이 예상선과 완전히 겹치는데, 그 위에 점선을 덧그리면 실선이 점선처럼
     보여서 차트가 망가집니다
   - 같은 카드 아래에 **목표 도달 확률** — 백분율 + 게이지 +
     `1,000번 굴려 435번 목표를 넘겼습니다` (횟수는 실제로 굴린 경로 수를 그대로 씁니다)
3. **슬라이더 4개** — `매월 적립` / `은퇴 연도` / `연 기대수익률` / `연 변동성`
   - 계획값과 다르면 숫자 색이 바뀝니다
4. **분포 3줄** — `잘 안 풀리면 (하위 10%)` / `예상` / `잘 풀리면 (상위 10%)`
5. **[되돌리기] [계획에 반영]** — 계획과 같으면 둘 다 비활성
6. **고지 문구** — "입력한 가정에 따른 계산이며 미래 수익을 보장하지 않습니다."

### 밴드의 가운데 선은 왜 p50이 아닌가

몬테카를로의 중앙값(p50)은 변동성 때문에 결정론적 예상선보다 **아래**에 놓입니다.
그런데 화면 맨 위의 큰 숫자와 차트의 가운데 선이 어긋나면 그건 버그로 읽힙니다.
그래서 **가운데 선과 헤드라인 숫자는 결정론적 예상값**(계획 탭과 같은 숫자)을 쓰고,
몬테카를로에서는 **폭(p10~p90)과 도달 확률만** 가져옵니다.

### 계산 시점

슬라이더를 끄는 동안 매 단계마다 1,000경로를 굴리지는 않습니다.
`.task(id:)` 로 120ms 디바운스를 두고, 손을 멈춘 뒤의 계산만 살아남습니다.
계산은 `Task.detached` 에서 돌고, 넘어가는 것은 값 타입(`ProjectionInput`·`Knobs`)뿐입니다.

### 아직 없는 것

| 항목 | 왜 미뤘나 |
|---|---|
| `은퇴 후 월 지출` 슬라이더 · 자산 고갈 나이 | 은퇴 이후 인출은 연금 소득 모델이 들어와야 계산됩니다. 그전에 추정하면 틀린 숫자를 크게 보여주게 됩니다 (`Projection` 은 은퇴 시점에서 멈춥니다) |
| 시나리오 저장·비교 (최대 3개 겹쳐 보기) | 밴드 하나를 제대로 그리는 것이 먼저입니다 |
| 슬라이더 길게 눌러 정밀 입력 | 계획 탭에서 정확한 값을 넣을 수 있습니다 |

## 2.6 더보기 탭

### 2.6.1 운용 원칙
번호가 매겨진 목록. 각 항목:
- 제목 + 부연 (1페이지 그대로)
- **점검 유형** 선택: 자동 점검 / 텍스트만
- 자동 점검이면 파라미터 (예: 상한 4%, 적용 범위 = 아빠 계좌)
- 현재 상태 배지: `준수` / `위반 (4.6%)`
- 점검은 매주 토요일 입력 직후 자동 실행 → 결과는 점검 완료 화면과 현황판에

### 2.6.2 유의사항 · 할 일
카테고리별 그룹: `세금·규제` / `연간 한도` / `기한` / `메모`
- 기한 있는 항목은 남은 일수와 체크박스, 로컬 알림 설정
- 연간 한도 항목은 사용률 게이지 (연금저축 578/600만)
- 완료 항목은 접어 보관, 매년 갱신되는 항목은 반복 설정

### 2.6.3 1페이지 내보내기
- 현재 데이터로 A4 1페이지 레이아웃 렌더 (`ImageRenderer` → PDF/PNG)
- 미리보기 → `ShareLink`로 공유·인쇄·파일 저장
- 옵션: 금액 표시/가리기, 포함할 섹션 선택

### 2.6.4 설정
기준 통화 · **주간 점검 알림(요일·시각·재알림·금액 노출)** · iCloud 동기화 상태 ·

## 2.8 자산 진단 (더보기 → 자산 진단, 현황판에 요약)

**가장 큰 원칙: 최종 투자 목적은 노후준비다.** 화면 맨 위에 그 문장을 두고,
여섯 규칙은 전부 "이게 은퇴 시점의 나에게 무슨 뜻인가"로 환원됩니다.
수익률을 올리는 규칙이 아니라 **노후 준비를 망치지 않는** 규칙들입니다.

### 상태는 넷

| 상태 | 뜻 |
|---|---|
| `지킴` | 기준 안에 있다 |
| `주의` | 아직 괜찮지만 경계에 가까워졌다 |
| `조치` | 기준을 벗어났다. 할 일이 있다 |
| `입력 필요` | 판단에 필요한 값이 아직 없다 — **모르면 모른다고 한다** |

`위반` 이 아니라 `조치` 입니다. 규칙은 막지 않고 알리며, 무엇을 하면 되는지까지
말해야 규칙이 삽니다 (2.7의 "규칙 위반은 경고하되 막지 않는다").

### 여섯 규칙

| # | 규칙 | 기본값 | 판정 |
|---|---|---|---|
| 1 | **은퇴 필요 자금** — 연 생활비 ÷ 인출률 | 인출률 4% (= 25배) | 은퇴 시점 **예상**이 필요액의 90% 미만이면 조치 |
| 2 | **부동산 비중** — 부동산 + 전세보증금 | 상한 35% | 상한 초과면 조치, 상한의 90%부터 주의 |
| 3 | **국가 배분** — 투자자산 기준 | 미국 60% ±5%p | 오차 밖이면 주의, 오차의 두 배 밖이면 조치 |
| 4 | **세제혜택 계좌** — 채우는 순서 | IRP → 연금저축 → ISA → 일반 | 남은 한도가 있으면 주의, 연말 3개월 안이면 조치 |
| 5 | **자산이 두 배 되는 시점** — 72의 법칙 | — | 판정하지 않는다. 눈금이다 |
| 6 | **선저축 비율** | 월 소득의 10% 이상 | 기준 미만이면 주의, 기준의 80% 미만이면 조치 |

### 설계에서 신경 쓴 것

- **1번은 지금 잔고가 아니라 은퇴 시점 예상으로 판단합니다.** 아직 은퇴하지
  않았는데 "12억 필요한데 3억뿐"이라고 하면 규칙이 무의미해집니다.
- **25배를 상수로 박지 않았습니다.** 인출률을 3.5%로 바꾸면 약 28.6배가 됩니다.
- **5번은 두 숫자를 나란히 보여 줍니다.** 72의 법칙은 적립을 세지 않습니다.
  `72÷8=9년` 옆에 `적립까지 세면 6년`을 함께 두지 않으면 규칙이 거짓말이 됩니다.
  뒤 숫자는 `Projection` 의 `자산 2배` 마일스톤에서 가져옵니다.
- **4번은 앱이 세법을 따라가지 않습니다.** 계좌 한도는 사용자가 계좌 화면에서
  직접 넣습니다. 숫자를 앱에 박아 두면 세법이 바뀐 뒤 **조용히 틀린 조언**을
  하게 됩니다 — 이 앱에서 가장 피하려는 실패입니다.
- **기준은 전부 사용자가 바꿉니다.** 기본값은 널리 쓰이는 수치일 뿐 정답이
  아닙니다. 앱이 정답을 아는 척하면 규칙이 사용자 것이 되지 않습니다.

### 현황판에는 요약만

숫자 셋(`조치 · 주의 · 지킴`)과 가장 급한 항목 한 줄만 둡니다. 매주 보는 화면에
여섯 규칙을 다 펼치면 무거워집니다. 누르면 진단 화면으로 넘어갑니다.

### 아직 없는 것

| 항목 | 왜 |
|---|---|
| 채우는 순서 직접 바꾸기 | 지금은 상수(IRP → 연금저축 → ISA)입니다. 순서를 바꾸는 UI 는 규칙이 자리를 잡은 뒤에 |
| 규칙 추가·삭제 | 여섯 개를 먼저 제대로 만드는 것이 순서입니다 |
| 진단 결과 이력 | 지금은 매번 현재 값으로 계산합니다. "언제부터 조치였나"는 기록이 쌓인 뒤에 |

## 2.7 화면 전반 규칙

| 규칙 | 이유 |
|---|---|
| 사실(과거)과 추정(미래)은 항상 시각적으로 다르게 그린다 | 예측을 사실로 착각하면 위험한 결정을 한다 |
| 큰 금액은 `3억 273만` 형태의 한국식 축약, 상세는 원 단위 | 억/만 단위가 직관적이다 |
| 증감은 색 + 부호 + 화살표 3중 표기 | 색맹 접근성 |
| 저장 버튼 없이 즉시 반영 | 입력 마찰 최소화. 실수는 되돌리기(Undo)로 처리 |
| 규칙 위반은 경고하되 막지 않는다 | 예외는 항상 있고, 사용자가 자기 돈의 주인이다 |
| 빈 상태는 항상 "다음 한 걸음"을 제시한다 | 온보딩을 끝까지 끌고 간다 |
| 입력을 끝내면 반드시 보상을 보여준다 | 손으로 적는 수고에 값이 있어야 다음 주에도 한다 |
| 연속 기록을 끊었다고 나무라지 않는다 | 죄책감은 앱을 지우게 만든다. 다시 시작하기 쉽게만 한다 |
| 모든 예측 화면에 고지 문구 | 정직성 + 규제 리스크 회피 |
