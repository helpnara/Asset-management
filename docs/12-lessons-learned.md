# 배운 것 — 다음 아이폰 앱을 만들 때 같은 실수를 안 하려고

`느린 부자의 기록` 을 2026-09-05 부터 맥 없이 만들면서 겪은 시행착오를
**다음 앱에 그대로 가져갈 수 있는 규칙**으로 추렸다. 사건의 자세한 경위는
[08-feedback](08-feedback.md)·[09-family-sharing](09-family-sharing.md)·
[06-testflight](06-testflight.md) 에 있고, 여기에는 **왜 그랬고 다음엔 어떻게
하나**만 남긴다.

| | |
|---|---|
| 기간 | 2026-09-05 ~ 09-12 (8일) |
| 빌드 | TestFlight 74개 · 커밋 443개 |
| 접수 항목 | 142개 (실기기 피드백) |
| 환경 | 맥 없음 · Claude Code 원격(리눅스) + GitHub Actions macOS 러너 + TestFlight |

새 앱을 시작할 때는 **맨 아래 체크리스트**만 읽어도 된다. 각 줄이 왜 있는지가
궁금할 때 위로 올라온다.

## 0. 한 줄씩 — 제일 비쌌던 열 가지

1. **공유할 건지 먼저 정하고 저장 계층을 고른다.** SwiftData 는 `CKShare` 를 못 한다. 옮기는 데 4차 절반이 들었다.
2. **스키마는 세 파일이 한 몸이다.** 모델 · `@NSManaged` 선언 · CloudKit `.ckdb`. 하나만 고치면 화면 값 하나가 조용히 빈다. CI 가 대조한다.
3. **CloudKit Production 은 저절로 안 생긴다.** Development 에 자동 생성 → 사람이 콘솔에서 Deploy. 시스템 타입(`cloudkit.share`)도 마찬가지다.
4. **체험(샘플) 자료를 실제 저장소에 넣지 않는다.** 아내 폰에서 동기화 자료와 섞였다. 메모리 컨테이너로 분리한다.
5. **"없어진 것" 은 스크린샷에 안 나온다.** 갈아타기 뒤 자동 저장이 사라졌는데 화면은 같았다. 첫 검사는 "껐다 켜서 그대로인가".
6. **앱이 죽으면 크래시 로그부터.** 로그 없이 세 바퀴를 추측으로 돌았고 그중 둘은 새 버그를 심었다.
7. **되돌릴 수 없는 서버 작업은 자동으로 돌리지 않는다.** 백업 뒤 사람이 버튼 한 번.
8. **글꼴·폭을 숫자로 못 박지 않는다.** 275곳을 나중에 고쳤다. 첫날부터 `Font.scaled` 하나로 통한다.
9. **빌드는 "착수하자" 에만.** 하루에 빌드 열두 개를 찍고 나서 정한 규칙이다. 이슈는 모아서 한 번에.
10. **기댓값을 지어내지 않는다.** 컴파일 못 하는 환경에서는 파이썬으로 독립 계산해 대조한다. 복리 테스트 오류를 이렇게 잡았다.

## 1. 시작 전에 정할 것 — 설계

### 저장 계층은 요구사항 끝까지 보고 고른다

- **사건.** 1차에 SwiftData + CloudKit 으로 시작했다(ADR-0001). 4차 "가족 공유" 에서
  SwiftData 가 `CKShare` 를 지원하지 않는 것을 확인하고 Core Data 로 옮겼다.
  스키마 12개 모델을 다 옮기는 데 4차의 절반이 들었고, 옮기는 과정에서 자동 저장이
  사라지고 저장소 경로가 어긋날 뻔했다.
- **규칙.** "누구와 나눌 것인가" 를 먼저 묻는다. 한 사람이 여러 기기면 SwiftData 로
  충분하다. **다른 Apple ID 와 공유하면 처음부터 `NSPersistentCloudKitContainer`.**
- **함께 정해 둘 것.** CloudKit 제약(유니크 제약 없음 · 모든 속성 기본값 · 모든 관계
  옵셔널)을 첫 모델부터 지킨다. 나중에 붙이려면 모델을 다시 만든다.

### 금액은 정수, 반올림은 한 곳

- `Money`(최소 단위 정수) · `Quantity`(스케일 10⁸) · `Ratio`(bp). `Double` 은
  몬테카를로 하나뿐이다. 반올림은 `Decimals` 한 곳.
- **왜 값했나.** 시뮬레이션에서 "같은 연 8% 인데 22억 · 34억"(63번) 같은 불일치가
  났을 때 원인이 반올림이 아니라 순서(적립 → 수익)라는 것을 1원 단위로 대조해
  잘랐다. `Double` 이었으면 오차인지 버그인지부터 헷갈렸을 것이다.

### 순수 로직은 별도 패키지로

- `Packages/Core` 는 Foundation 만 쓴다. SwiftUI · Core Data 를 import 하지 않는다.
- **왜.** 원격 세션(리눅스)에서 검증할 수 있는 범위가 이것뿐이고, CI 에서도 시뮬레이터
  없이 수 초에 돈다. 이 경계가 무너지면 모든 검증이 시뮬레이터로 밀린다.

### 외부 네트워크를 안 쓰기로 한 것이 위험을 크게 줄였다

- 시세 · 환율을 가져오지 않는다(ADR-0005). 통화별 입력 · 환율 환산은 만들었다가
  걷어냈다 — 사용자가 어차피 원화로 환산해 적는다.
- **규칙.** 첫 버전은 "사용자가 손으로 적는 것" 만으로 성립하는지 본다. 외부 의존
  하나가 심사(개인정보 · 네트워크 권한) · 오류 처리 · 오프라인 동작을 전부 끌고 온다.

### 되돌리기 비싼 결정은 ADR 로 남긴다

- `docs/adr/` 다섯 건. 세션이 바뀌어도 "왜 이렇게 했더라" 를 다시 묻지 않게 한다.
- **규칙.** 저장 계층 · 숫자 표현 · 동기화 방식 · 공유 모델 · 입력 방식은 ADR 감이다.
  나머지는 08 같은 작업 기록으로 충분하다.

### "1.0 이 무엇인가" 를 처음에 적는다

- 1.0 = 우리 가족 넷(TestFlight), 2.0 = 모두(App Store) 로 나누고, "1.0 안정화
  판단 기준" 여덟 줄을 로드맵에 표로 뒀다. Claude 는 세션을 넘어 기억하지
  못하므로 **그 표가 기억**이다.
- **규칙.** 끝나는 조건을 표로 만들고, 채워질 때 날짜를 적는다. 없으면 기능이 끝없이
  는다.

### 앱 이름과 화면 제목을 섞지 않는다

- 앱 이름 `느린 부자의 기록`, 화면 상단 `우리 가족 노후자금 준비` 는 사용자가 바꾸는
  계획 제목(`Plan.title`)이다. 초반에 둘이 섞여 문서 · 공유 카드 · 1페이지 서명에서
  제각각이었다.
- **규칙.** 앱 이름 · 번들 식별자 · 화면 제목을 첫날 한 표에 적는다.

## 2. 맥 없이 만드는 환경 — CI 가 컴파일러다

### 원격 세션은 컴파일을 못 한다

- 리눅스 컨테이너에는 Xcode 도 Swift 툴체인도 없고 `download.swift.org` 도 막혀
  있다. SwiftUI · Core Data 는 리눅스 Swift 로도 안 된다.
- **규칙.** 코드는 쓰되, **컴파일 · 실행 · 스크린샷은 전부 CI 가 한다.** 푸시 →
  CI 로그 · `screenshots/` 로 확인. 문서만 고친 푸시는 `paths-ignore` 로 CI 를
  건너뛴다.

### 검증 사다리 — 위에서 잡을 수 있는 것을 아래로 흘리지 않는다

| 심판 | 잡는 것 | 한 바퀴 비용 |
|---|---|---|
| 파이썬 대조 (기댓값) | 계산 로직 | 초 |
| 체크 스크립트 (`Tools/`) | 세 스키마 파일이 서로 맞는지 | 초 |
| Core `swift test` | 순수 로직 | 수 초 |
| 앱 빌드 (`momc` 포함) | 문법 · 모델 문법 | 10분 |
| 런타임 검사 (`check-cloudkit-model.swift`) | 런타임이 실제로 읽는 모델 | 10분 |
| 시뮬레이터 스크린샷 | 화면 | 15분 |
| 실기기 (TestFlight) | 자격 · 계정 · 알림 · 동기화 | 30분 + 사람 |

- **사건.** 옮긴 모델이 파일로는 맞는데 런타임 판본 해시가 달랐다(09). 그 칸을 잡을
  심판이 없어 실기기까지 내려갔다.
- **규칙.** 실기기에서 뭔가 잡히면 **"어느 칸에서 잡았어야 했나"** 를 묻고 그 칸에
  심판을 세운다.

### 스크린샷 심판은 믿을 만하게 만들어야 심판이다

- **빈 스크린샷.** iPad 촬영이 118,630바이트짜리 빈 화면을 내놓았다 → 대기
  `SHOOT_WAIT=12` · 재시도 4회.
- **홈 화면 스크린샷.** 첫 장(웰컴)이 앱이 뜨기 전 홈 화면을 찍었다 → 2MB 넘으면
  실패로 간주하는 가드.
- **큰 글씨 스크린샷이 보통 글씨와 바이트 단위로 같았다.** 글꼴이 전부 고정 크기라
  Dynamic Type 이 아무것도 안 바꿨다는 뜻이었다. 이 한 장이 §4 의 275곳 수정을
  끌어냈다.
- **규칙.** 스크린샷 단계에 (1) 빈 화면 재시도 (2) 크기 가드 (3) **큰 글씨 한 장**
  (4) iPad 한 장을 처음부터 넣는다.

### "없어진 것" 은 스크린샷에 안 나온다

- 갈아타기 내내 심판은 "화면이 이전과 같은가" 였다. 자동 저장처럼 **원래 저절로
  되던 일**은 없어져도 화면에 자국이 없다.
- **규칙.** 큰 변경 뒤 확인 목록 첫 줄은 **"껐다 켜서 그대로인가"**. "무엇이
  달라졌나" 만큼 **"무엇이 저절로 되고 있었나"** 를 센다.

### 러너에서만 나는 문제들

| 증상 | 원인 | 다음엔 |
|---|---|---|
| `maximum number of certificates` | 러너가 매번 새 기계라 개발 인증서를 계속 발급 | 개발자 사이트에서 오래된 `Created by Xcode` 폐기. 배포용은 건드리지 않는다 |
| `The Xcode build system has crashed` 가 **같은 자리에서 두 번** | 문자열 안의 곧은 따옴표 `"…"` 로 소스가 깨짐 | 두 번 같은 자리면 러너 탓이 아니다. 안내 문구의 강조는 `**…**` |
| `pip3 install` 이 PEP 668 로 거부 | 시스템 파이썬 보호 | `python3 -m venv` 뒤 설치 |
| 워크플로가 커밋을 못 함(403) | 기본 토큰이 읽기 전용 | `permissions: contents: write` |
| 결과물을 못 받음(커밋 실패 시) | 커밋 뒤에 아티팩트 업로드 | **아티팩트 업로드를 커밋보다 앞에** |
| 푸시 거부(non-fast-forward) | CI 가 스크린샷을 커밋함 | `git pull --rebase` 뒤 푸시. 푸시하면 진행 중 CI 가 취소된다(`cancel-in-progress`) |
| 릴리스 노트 깨짐 | JSON 에 한글·따옴표 | `\u` 이스케이프로 넣는다 |

### 빌드 규율 — "착수하자" 에만

- 하루에 빌드 48→60 을 찍고 나서 정했다. 이슈 한 건마다 빌드하면 확인 왕복이 빌드
  수만큼 든다.
- **규칙.** (1) 이슈는 08 표에 번호 붙여 쌓는다 (2) 5~10개 모이면 착수 여부를 묻는다
  (3) 사용자가 "착수하자" 할 때만 CI · TestFlight 를 돌린다 (4) **빌드마다 체크리스트를
  같이 준다** — 사용자는 "1~7 확인 완료" 로 답한다. 자료가 사라지거나 어긋나는 문제만
  예외로 바로 고친다.

## 3. 스키마 · CloudKit — 조용히 실패하는 곳

### 세 파일이 한 몸이다

- `.xcdatamodeld` · `Generated/*+CoreDataProperties.swift` · `Tools/cloudkit/slowrich.ckdb`.
- **빠진 `@NSManaged` 선언은 컴파일을 통과하고 화면 값 하나가 조용히 빈다.** 그래서
  CI 의 대조 스크립트가 유일한 심판이다.
- **규칙.** 칸을 더하는 절차를 문서에 번호로 적어 두고(06) 그대로 따른다:
  모델 → 선언 → `generate-ckdb.py` → 체크 스크립트 → `Backup` 옵셔널 필드 →
  Development 적용 → **사람이 Production 배포**.

### Production 은 저절로 안 생긴다

- 저장 계층은 Development 에서만 레코드 타입을 자동 생성한다. TestFlight 는
  Production 을 쓴다. 엔타이틀먼트로 못 바꾼다. 맥이 없으면 Development 조차 비어
  있다.
- 해결: `CKTool JS` 는 Node 라 리눅스 러너로 충분하다. 워크플로가 `.ckdb` 를
  Development 에 밀어 넣고 사람이 콘솔에서 Deploy.
- **`cloudkit.share` 같은 시스템 타입도 같은 규칙이다.** 앱이 Development 에서 처음
  공유를 시도할 때 생기는데 그 일이 영영 안 일어난다. `.ckdb` 에 같이 뽑고 이름에
  점이 있어 따옴표로 감싼다.
- **모델을 고치면 다시 올린다.** 안 올리면 새 필드가 iCloud 에 안 가는데 화면에서는
  티가 안 난다. 옮기기 기능이 `Cannot create or modify field 'CD_moveReceipt' …
  in production schema` 로 막힌 것이 그 예다.

### 갈아탈 때 저장소 파일은 같은 것이어야 한다

- SwiftData 기본 경로 `Application Support/default.store`. 다른 경로를 열면 앱은
  멀쩡히 뜨는데 **빈 화면**이고, 사용자는 "몇 달치가 날아갔다" 를 본다.
- **규칙.** 경로를 못 박고, 엔티티 · 속성 이름을 그대로 쓴다(`.ckdb` 의 `CD_` 이름이
  증거). **옮기기 전에 백업 기능부터 만든다** — 40번 백업이 미리 값한 자리다.

### 두 기기가 같은 사람을 다르게 부른다

- 참가자 기기에서 읽은 사용자 ID 가 자리표시였고 관리자 폰의 `editorIDs` 와 영영
  안 맞았다.
- **규칙.** 서로 견줄 ID 는 언제나 서버가 준 절대 이름(`fetchUserRecordID`)으로.
  진단 화면에 "ID 꼬리" 한 줄을 두면 동기화 지연으로 착각하는 한 바퀴를 아낀다.

### 뿌리를 새로 만들 때 "앞으로 만들 것" 과 "이미 있는 것" 을 따로 센다

- 새 레코드는 공유 존에 붙였는데 이미 개인 존에 올라간 레코드는 아무도 안 맡았다.
  두 기기가 있어야 보이는 실패라 **합격 기준을 먼저 적어 둔 것**이 유일한 그물이었다.

### 되돌릴 수 없는 서버 작업은 사람이 누른다

- 존 사이 옮기기는 서버에서 **삭제를 포함**한다. 화면에서 성공처럼 보여도 그렇다.
- **규칙.** 자동으로 돌리지 않는다. "먼저 백업을 받으셨나요?" → 한 기기에서만 →
  버튼 한 번.

### 참가자 기기에도 개인 저장소가 있다

- 참가자 폰에서 공유를 받기 전에 만든(또는 체험으로 생긴) 레코드가 개인 저장소에
  남아 화면에 섞였다. `deleteStrays()` 와 "개인 저장소의 기록 N건 지우기" 버튼으로
  풀었다.
- **규칙.** 공유 앱은 **역할별 저장소 상태**를 화면에서 볼 수 있게 한다.

### 앱이 죽으면 크래시 로그부터

- `UICloudSharingController` 준비 핸들러가 메인에서 수백 건을 옮겨 iOS 가 앱을 죽였다.
  로그를 세 바퀴 늦게 요청했고 그동안 API 사용법을 추측으로 바꿨다. 둘은 새로 심은
  버그였다.
- **규칙.** 사용자에게 **설정 → 개인정보 보호 → 분석 데이터** 의 크래시 로그를 먼저
  받는다. 그다음에 고친다.

## 4. Swift 6 · SwiftUI 코드에서 반복된 것

### 동시성

- **`NSManagedObject` 를 `async` 경계 너머로 넘기지 않는다.** `Sendable` 이 아니다.
  Int · Date · Money 만 뽑아 `Sendable` 구조체로 건넨다. 세 번 밟고 세 번 다 값으로
  풀었다. `@preconcurrency` 로 검사를 끄지 않는다.
- `@MainActor` 함수를 nonisolated 에서 부르면 막힌다 → 정말 메인이 필요한지 묻고
  아니면 뗀다(`makeTrialContainer`).
- `onPreferenceChange` 클로저는 `Sendable` 이라 `@State` 를 직접 못 고친다 →
  `Task { @MainActor in … }`.

### Dynamic Type 은 첫날부터

- **사건.** 글꼴 275곳이 `.system(size:)` 였고, 큰 글씨 스크린샷이 보통과 바이트까지
  같았다. 고치고 나니 이번엔 **글자를 담는 칸**(폭 · 높이 · 여백)이 고정이라 캡션이
  겹치고 배지가 줄 바꿈됐다.
- **규칙.**
  - 글꼴은 `Font.scaled(_:weight:)` 하나로. 숫자는 `Font.figure` (tabular · 우측 정렬).
  - 글자를 담는 길이는 `Font.scaledLength(_:)`. 종이(PDF)만 예외.
  - 배지 · 짧은 라벨: `lineLimit(1)` + `fixedSize`.
  - 범례 · 표: `ViewThatFits` 로 가로 → 세로 · 가로 스크롤을 준비한다.
  - 세로 축 텍스트필드(`axis: .vertical`)는 `.top` 정렬 (`.firstTextBaseline` 이 어긋난다).
  - CI 스크린샷에 **큰 글씨 한 장**을 넣어 증명한다.

### 핀치 줌은 UIKit 으로

- SwiftUI 만으로 세 바퀴 돌았다: 프레임이 측정값×배율을 다시 제안해 **레이아웃
  되먹임**으로 iPad 가 멈춤 → `.gesture` 가 `ScrollView` 에 먹힘(`.simultaneousGesture`
  로 잠시) → 그래도 툭툭 끊김.
- **규칙.** 확대 · 축소 · 관성은 `UIScrollView` 를 `UIViewRepresentable` 로 싼다.
  내용은 2× 로 그리고 `fixedSize`, 폭 맞춤 배율을 최소로, 그 4배를 최대로.
  **`transform` 이 걸린 뷰에 frame 을 주면 초기 위치가 어긋난다** — 자연 크기가
  바뀔 때 다시 맞춘다.

### 화면에서 반복된 작은 것들

| 사건 | 규칙 |
|---|---|
| 다크 모드에서 화면마다 톤이 제각각 (1번) | 색은 토큰 하나(`DesignSystem`)로. 화면에서 직접 색을 적지 않는다 |
| 숫자 키패드를 못 내려 갇힘 (2번) | 툴바 `완료` 를 **한 곳**에서 만든다. 여러 곳에 두면 `완료` 가 여럿 생긴다(빌드 14) |
| Face ID 계속 실패 (4번) | `NSFaceIDUsageDescription` 을 첫날 Info.plist 에. 잠금은 `.inactive` 가 아니라 `.background` 에서 (인증 창이 뜨면 앱이 `.inactive` 가 된다). 취소는 오류가 아니다. 시뮬레이터는 Face ID 를 안 타서 CI 가 못 잡는다 |
| 적립 0원이면 그래프 깨짐 (3번) | 경계값(0 · 음수 · 빈 배열)을 테스트 첫 줄에 |
| 시작 화면이 항상 8월 (141번) | "지금" 을 기본값으로. 고정 오프셋을 두지 않는다 |
| 같은 날 일기가 둘 (57번) | 날짜를 옮길 때 충돌을 막고 이유를 말한다 |

### 알림

- 매주 토요일 반복 알림은 잘 갔지만, "오늘 썼으니 오늘은 울리지 마" 는 반복 알림으로
  못 한다 → 일회성 요청 7개를 미리 걸어 두고 오늘 쓰면 오늘 것만 뺀다(114번).
- **가정은 날짜와 함께 확인한다.** "토요일 아침 알림이 온다" 는 로드맵 A4 였고
  2026-09-12 실기기에서 확인해 날짜를 적었다.

## 5. 사용자 자료 — 한 번 잃으면 끝

- **실제 금액 · 기관명 · 계좌를 커밋하지 않는다.** 사용자가 보내는 화면 캡처에는
  실제 금액이 있다. 문서에 옮길 때는 지어낸 숫자로 바꾼다. 스토어 스크린샷은 체험
  자료로 찍는다.
- **백업 · 되돌리기를 큰 변경 전에 만든다.** 갈아타기 · 옮기기 · 공유 전부 백업이
  먼저 있었기에 되돌아갈 길이 있었다.
- **체험 자료는 메모리 컨테이너에.** 실제 저장소에 씨앗을 뿌리면 동기화 자료와 섞인다.
  `TrialMode` 가 별도 컨테이너를 들고 `viewContext` 를 갈아 끼운다. 체험 중 배너 하나
  ("체험 자료입니다 · 실제 금액이 아닙니다")를 항상 띄운다.
- **모든 삭제에 확인 장치** (16번). "전부 지우기" 는 문구를 타이핑하게 한다.
- **"데이터가 사라진 적이 없다" 4주 시계**는 되돌릴 수 없는 작업을 한 날부터 다시
  센다.

## 6. 계산 — 기댓값을 지어내지 않는다

- 컴파일 못 하는 환경에서 테스트 기댓값을 손으로 적으면 **테스트가 버그를
  승인**한다. 복리 테스트 오류를 파이썬 대조로 잡았고, 국민연금 추정(125번)도
  A값 · 상한 · 하한 · 최소 가입 개월을 파이썬으로 계산한 값만 넣었다.
- **규칙.** 수치 기댓값은 다른 언어 · 다른 방법으로 한 번 더 계산해 1원까지 맞춘 뒤
  적는다. 테스트 커밋 메시지에 "기댓값은 파이썬으로 대조" 라고 남긴다.
- 같은 입력에 두 결과(63번)가 나오면 **어느 쪽이 맞는지**를 독립 계산으로 먼저
  정한다. 둘을 같게만 만들면 둘 다 틀릴 수 있다.

## 7. 스토어 준비 — 테스트하는 동안 미리

- **개인정보 처리방침 URL 은 첫 빌드 전에.** GitHub Pages 로 **방침만** 낸다
  (`/docs` 전체를 내면 설계 문서가 다 공개된다 → `Tools/site/build.py` 가 한 장만
  만든다). App Store Connect 에서 입력하는 곳은 `App Store → 앱이 수집하는 개인정보`
  이지 앱 정보가 아니다.
- **스크린샷 크기.** iPhone 칸이 6.9" 만으로는 안 받고 **6.5"(1284×2778 또는
  1242×2688)** 를 요구했다. iPad 는 13"(2064×2752). CI 워크플로가 Pro Max · iPad Pro 로
  찍고 캡션을 얹어 두 크기를 다 만들어 둔다.
- **상표 검색(KIPRIS)** 을 이름 정할 때 한 번 한다.
- **"1위" 의 뜻을 먼저 정한다.** 검색 1위 · 평점 · 에디터 추천처럼 잴 수 있는 것으로.
  부제 · 키워드 · 설명은 그 목표에서 나온다(10). 출시 날짜를 정하면 준비 목록이
  저절로 잘린다.
- **후기 요청은 기분 좋은 순간에, 90일에 한 번, 체험 중엔 안 한다.**

## 8. Claude 와 일하는 방식 — 이게 제일 많이 아꼈다

- **문서가 코드보다 앞선다.** 헷갈리면 `docs/` 를 먼저 읽는다. `CLAUDE.md` 에 규칙과
  "기억해 둘 것" 을 두고, 세션이 바뀔 때마다 그것을 기억으로 쓴다.
- **이슈는 번호 · 상태 · 빌드 번호.** 🔴🟡🔵🟢🟠 다섯 상태. 뒤엎은 것(🟠)은 어느
  항목이 대신하는지 적는다. 사용자는 "1~7 확인 완료" 로만 답해도 된다.
- **가정 표.** 확인 안 된 가정을 A1… 으로 적고 확인한 날짜를 채운다. 로드맵의
  "1.0 안정화 판단 기준" 도 같은 꼴이다.
- **빌드마다 체크리스트 + 사용자가 할 일.** 앱 안에서 확인할 것과 콘솔 · 사이트에서
  할 것을 나눈다.
- **크래시 로그 · 진단 정보 · ID 꼬리**처럼 사용자가 **복사해 붙일 수 있는 것**을
  앱에 넣는다. "동기화가 안 돼요" 를 한 바퀴에 끝낸다.
- **사용자가 두 번 "확인해줘" 하면 러너 탓으로 돌리지 않는다.** 따옴표 사건, 핀치 줌
  사건 다 그랬다.
- **끝난 뒤 회고를 문서로 남긴다.** 이 문서다.
