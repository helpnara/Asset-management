## 0. 한 줄씩 — 제일 비쌌던 열세 가지

1. **공유할 건지 먼저 정하고 저장 계층을 고른다.** SwiftData 는 `CKShare` 를 못 한다. 옮기는 데 4차 절반이 들었다.
2. **스키마는 세 파일이 한 몸이다.** 모델 · `@NSManaged` 선언 · CloudKit `.ckdb`. 하나만 고치면 화면 값 하나가 조용히 빈다. CI 가 대조한다.
3. **CloudKit Production 은 저절로 안 생긴다.** Development 에 자동 생성 → 사람이 콘솔에서 Deploy. 시스템 타입(`cloudkit.share`)도 마찬가지다.
4. **체험(샘플) 자료를 실제 저장소에 넣지 않는다.** 아내 폰에서 동기화 자료와 섞였다. 메모리 컨테이너로 분리한다.
5. **"없어진 것" 은 스크린샷에 안 나온다.** 갈아타기 뒤 자동 저장이 사라졌는데 화면은 같았다. 첫 검사는 "껐다 켜서 그대로인가".
6. **앱이 죽으면 크래시 로그부터.** 로그 없이 세 바퀴를 추측으로 돌았고 그중 둘은 새 버그를 심었다.
7. **되돌릴 수 없는 서버 작업은 자동으로 돌리지 않는다.** 백업 뒤 사람이 버튼 한 번.
8. **글꼴·폭을 숫자로 못 박지 않는다.** 275곳을 나중에 고쳤다. 첫날부터 `Font.scaled` 하나로 통한다.
9. **빌드는 "착수하자" 에만.** 하루에 빌드 열두 개를 찍고 나서 정한 규칙이다. 이슈는 모아서 한 번에.
10. **기댓값을 지어내지 않는다.** 컴파일 못 하는 환경에서는 파이썬으로 독립 계산해 대조한다. 복리 테스트 오류를 이렇게 잡았다.
11. **체크리스트는 코드에서 확인한 뒤 준다.** 화면 이름 그대로의 경로 · 보이는 조건까지. 10-09 하루에 세 번 틀렸다 (§10).
12. **화면이 다시 만들어지면 `@State` 는 처음으로 돌아간다.** 아이패드를 돌리자 점검 창이 닫히고 "열 때 값" 을 잃었다. 띄우는 창 · 장부는 화면 밖에 (§10).
13. **입력칸은 사라질 때도 쓴다.** `취소` · `나중에` 뒤에 친 값이 되살아났다 — 두 빌드에 걸쳐 두 번. 닫기 전에 "버릴 칸" 을 정한다 (§10).

## 1. 시작 전에 정할 것 — 설계

### 저장 계층은 요구사항 끝까지 보고 고른다

- **사건.** 1차에 SwiftData + CloudKit 으로 시작했다(ADR-0001). 4차 "가족 공유" 에서
  SwiftData 가 `CKShare` 를 지원하지 않는 것을 확인하고 Core Data 로 옮겼다.
  스키마 12개 모델을 다 옮기는 데 4차의 절반이 들었고, 옮기는 과정에서 자동 저장이
  사라지고 저장소 경로가 어긋날 뻔했다.
- **규칙.** "누구와 나눌 것인가" 를 먼저 묻는다. 한 사람이 여러 기기면 SwiftData 로
  충분하다. **다른 Apple ID 와 공유하면 처음부터 `NSPersistentCloudKitContainer`.**
- **함께 정해 둘 것.** CloudKit 제약(유니크 제약 없음 · 모든 속성 기본값 · 모든 관계
  옵셔널)을 첫 모델부터 지킨다. 나중에 붙이려면 모델을 다시 만든다.

### 금액은 정수, 반올림은 한 곳

- `Money`(최소 단위 정수) · `Quantity`(스케일 10⁸) · `Ratio`(bp). `Double` 은
  몬테카를로 하나뿐이다. 반올림은 `Decimals` 한 곳.
- **왜 값했나.** 시뮬레이션에서 "같은 연 8% 인데 22억 · 34억"(63번) 같은 불일치가
  났을 때 원인이 반올림이 아니라 순서(적립 → 수익)라는 것을 1원 단위로 대조해
  잘랐다. `Double` 이었으면 오차인지 버그인지부터 헷갈렸을 것이다.

### 순수 로직은 별도 패키지로

- `Packages/Core` 는 Foundation 만 쓴다. SwiftUI · Core Data 를 import 하지 않는다.
- **왜.** 원격 세션(리눅스)에서 검증할 수 있는 범위가 이것뿐이고, CI 에서도 시뮬레이터
  없이 수 초에 돈다. 이 경계가 무너지면 모든 검증이 시뮬레이터로 밀린다.

### 외부 네트워크를 안 쓰기로 한 것이 위험을 크게 줄였다

- 시세 · 환율을 가져오지 않는다(ADR-0005). 통화별 입력 · 환율 환산은 만들었다가
  걷어냈다 — 사용자가 어차피 원화로 환산해 적는다.
- **규칙.** 첫 버전은 "사용자가 손으로 적는 것" 만으로 성립하는지 본다. 외부 의존
  하나가 심사(개인정보 · 네트워크 권한) · 오류 처리 · 오프라인 동작을 전부 끌고 온다.

### 되돌리기 비싼 결정은 ADR 로 남긴다

- `docs/adr/` 다섯 건. 세션이 바뀌어도 "왜 이렇게 했더라" 를 다시 묻지 않게 한다.
- **규칙.** 저장 계층 · 숫자 표현 · 동기화 방식 · 공유 모델 · 입력 방식은 ADR 감이다.
  나머지는 08 같은 작업 기록으로 충분하다.

### "1.0 이 무엇인가" 를 처음에 적는다

- 1.0 = 우리 가족 넷(TestFlight), 2.0 = 모두(App Store) 로 나누고, "1.0 안정화
  판단 기준" 여덟 줄을 로드맵에 표로 뒀다. Claude 는 세션을 넘어 기억하지
  못하므로 **그 표가 기억**이다.
- **규칙.** 끝나는 조건을 표로 만들고, 채워질 때 날짜를 적는다. 없으면 기능이 끝없이
  는다.

### 앱 이름과 화면 제목을 섞지 않는다

- 앱 이름 `느린 부자`, 화면 상단 `우리 가족 노후자금 준비` 는 사용자가 바꾸는
  계획 제목(`Plan.title`)이다. 초반에 둘이 섞여 문서 · 공유 카드 · 1페이지 서명에서
  제각각이었다.
- **규칙.** 앱 이름 · 번들 식별자 · 화면 제목을 첫날 한 표에 적는다.

### 아이콘에 글자를 넣으려면 서체 파일을 함께 남긴다

- 2026-09-24 에 앱 이름을 `느린 부자의 기록` → `느린 부자` 로 줄였는데, 아이콘 띠에
  제목이 **그림으로** 박혀 있었다. 같은 서체로 다시 쓰려면 그 서체가 있어야 하는데
  없었다. 결국 **이미 그려진 글자를 오려 가운데로 옮기고 남은 자리를 배경색으로
  메웠다** (`Tools/retitle-icon.py`). 두 번 헛짚고 나서야 이음매가 안 보였다 —
  한 색으로 칠하면 네모가 비치고, 위아래 줄을 그대로 받으면 잡티가 세로줄이 된다.
- **규칙.** 아이콘에 글자를 넣는다면 ① 서체 파일과 ② 글자 없는 판을 저장소에
  함께 둔다. 애플 HIG 는 아이콘에 글자를 넣지 말라고 한다 — 안 넣는 쪽이 더 낫다.

### 글자를 바꿀 때는 공백을 지우고 찾는다

- 앱 이름을 바꾸면서 `느린 부자의 기록` 으로 grep 했더니 **다섯 자리가 안 걸렸다.**
  화면에 예쁘게 놓으려고 글자 사이에 스페이스를 넣은 곳이 넷(`느 린 부 자 의 기 록`),
  파일 이름이라 공백을 아예 뺀 곳이 하나(`느린부자의기록 백업 …json`)였다.
- **규칙.** 문구를 일괄로 바꿀 때는 줄에서 공백을 지운 뒤 비교한다.
  `re.sub(r'\s+', '', line)` 한 줄이면 다섯이 한 번에 나온다.
- **조사도 같이 깨진다.** 받침이 있던 말(`…기록`)이 없는 말(`…부자`)로 바뀌면
  `은/는` · `이/가` · `을/를` 이 전부 어긋난다. 스토어 설명문 첫 줄이
  `느린 부자은` 이 되어 있었다. 바꾼 말 뒤에 붙는 조사를 따로 훑는다.
- 더 큰 교훈: **내가 만든 체크리스트는 내가 놓친 것을 못 잡는다.** 사용자는
  체크리스트 열네 개를 다 통과시켰지만, 놓친 다섯은 애초에 목록에 없었다.
  사람이 훑는 검사와 기계가 훑는 검사는 놓치는 것이 다르므로 둘 다 있어야 한다.

### 이름을 시리즈로 묶을 거면 꼬리를 붙이지 않는다

- `느린 부자` · `느린 여백` · `느린 나이테` 처럼 묶으려면 **공통 낱말 하나 +
  앱마다 다른 낱말 하나**여야 한다. `~의 기록` 같은 꼬리가 셋 다 붙으면 시리즈가
  아니라 같은 이름 셋이 된다.
- 짧은 이름은 덤이 많다 — 홈 화면 아이콘 아래에서 안 잘리고, 아이콘 안의 글자도
  작은 크기에서 읽힌다.
- **규칙.** 두 번째 앱을 만들 생각이 있으면 첫 앱 이름을 지을 때 이미 시리즈로
  짓는다. 나중에 바꾸면 스토어 이름 · 상표 검색 · 아이콘 그림이 따라온다.

## 2. 맥 없이 만드는 환경 — CI 가 컴파일러다

### 원격 세션은 컴파일을 못 한다

- 리눅스 컨테이너에는 Xcode 도 Swift 툴체인도 없고 `download.swift.org` 도 막혀
  있다. SwiftUI · Core Data 는 리눅스 Swift 로도 안 된다.
- **규칙.** 코드는 쓰되, **컴파일 · 실행 · 스크린샷은 전부 CI 가 한다.** 푸시 →
  CI 로그 · `screenshots/` 로 확인. 문서만 고친 푸시는 `paths-ignore` 로 CI 를
  건너뛴다.

### 검증 사다리 — 위에서 잡을 수 있는 것을 아래로 흘리지 않는다

| 심판 | 잡는 것 | 한 바퀴 비용 |
|---|---|---|
| 파이썬 대조 (기댓값) | 계산 로직 | 초 |
| 체크 스크립트 (`Tools/`) | 세 스키마 파일이 서로 맞는지 | 초 |
| Core `swift test` | 순수 로직 | 수 초 |
| 앱 빌드 (`momc` 포함) | 문법 · 모델 문법 | 10분 |
| 런타임 검사 (`check-cloudkit-model.swift`) | 런타임이 실제로 읽는 모델 | 10분 |
| 시뮬레이터 스크린샷 | 화면 | 15분 |
| 실기기 (TestFlight) | 자격 · 계정 · 알림 · 동기화 | 30분 + 사람 |

- **사건.** 옮긴 모델이 파일로는 맞는데 런타임 판본 해시가 달랐다(09). 그 칸을 잡을
  심판이 없어 실기기까지 내려갔다.
- **규칙.** 실기기에서 뭔가 잡히면 **"어느 칸에서 잡았어야 했나"** 를 묻고 그 칸에
  심판을 세운다.

### 스크린샷 심판은 믿을 만하게 만들어야 심판이다

- **빈 스크린샷.** iPad 촬영이 118,630바이트짜리 빈 화면을 내놓았다 → 대기
  `SHOOT_WAIT=12` · 재시도 4회.
- **홈 화면 스크린샷.** 첫 장(웰컴)이 앱이 뜨기 전 홈 화면을 찍었다 → 2MB 넘으면
  실패로 간주하는 가드.
- **큰 글씨 스크린샷이 보통 글씨와 바이트 단위로 같았다.** 글꼴이 전부 고정 크기라
  Dynamic Type 이 아무것도 안 바꿨다는 뜻이었다. 이 한 장이 §4 의 275곳 수정을
  끌어냈다.
- **규칙.** 스크린샷 단계에 (1) 빈 화면 재시도 (2) 크기 가드 (3) **큰 글씨 한 장**
  (4) iPad 한 장을 처음부터 넣는다.

### "없어진 것" 은 스크린샷에 안 나온다

- 갈아타기 내내 심판은 "화면이 이전과 같은가" 였다. 자동 저장처럼 **원래 저절로
  되던 일**은 없어져도 화면에 자국이 없다.
- **규칙.** 큰 변경 뒤 확인 목록 첫 줄은 **"껐다 켜서 그대로인가"**. "무엇이
  달라졌나" 만큼 **"무엇이 저절로 되고 있었나"** 를 센다.

### 러너에서만 나는 문제들

| 증상 | 원인 | 다음엔 |
|---|---|---|
| `maximum number of certificates` | 러너가 매번 새 기계라 개발 인증서를 계속 발급 | 개발자 사이트에서 오래된 `Created by Xcode` 폐기. 배포용은 건드리지 않는다 |
| `The Xcode build system has crashed` 가 **같은 자리에서 두 번** | 문자열 안의 곧은 따옴표 `"…"` 로 소스가 깨짐 | 두 번 같은 자리면 러너 탓이 아니다. 안내 문구의 강조는 `**…**` |
| `pip3 install` 이 PEP 668 로 거부 | 시스템 파이썬 보호 | `python3 -m venv` 뒤 설치 |
| 워크플로가 커밋을 못 함(403) | 기본 토큰이 읽기 전용 | `permissions: contents: write` |
| 결과물을 못 받음(커밋 실패 시) | 커밋 뒤에 아티팩트 업로드 | **아티팩트 업로드를 커밋보다 앞에** |
| 푸시 거부(non-fast-forward) | CI 가 스크린샷을 커밋함 | `git pull --rebase` 뒤 푸시. 푸시하면 진행 중 CI 가 취소된다(`cancel-in-progress`) |
| 릴리스 노트 깨짐 | JSON 에 한글·따옴표 | `\u` 이스케이프로 넣는다 |

### 빌드 규율 — "착수하자" 에만

- 하루에 빌드 48→60 을 찍고 나서 정했다. 이슈 한 건마다 빌드하면 확인 왕복이 빌드
  수만큼 든다.
- **규칙.** (1) 이슈는 08 표에 번호 붙여 쌓는다 (2) 5~10개 모이면 착수 여부를 묻는다
  (3) 사용자가 "착수하자" 할 때만 CI · TestFlight 를 돌린다 (4) **빌드마다 체크리스트를
  같이 준다** — 사용자는 "1~7 확인 완료" 로 답한다. 자료가 사라지거나 어긋나는 문제만
  예외로 바로 고친다.

### 브랜치에 되돌려 커밋하는 워크플로가 돌 때는 푸시하지 않는다 (2026-10-03)

- 스토어 스크린샷 워크플로가 30분 걸려 찍어 놓고 마지막 `git push` 에서 **"fetch first" 로
  거절**됐다 — 그 사이 문서 커밋을 세 번 올렸다. CI 스크린샷 커밋(`[skip ci]`)도 같은 꼴이다.
- **다시 실행(re-run)은 답이 아니다.** 같은 커밋을 다시 받아 같은 이유로 또 밀린다. 취소하고
  **새로 실행(dispatch)** 해야 지금 브랜치 끝에서 시작한다.
- **규칙.** 되돌려 커밋하는 워크플로를 걸었으면 끝날 때까지 푸시를 모은다.

## 3. 스키마 · CloudKit — 조용히 실패하는 곳

### 세 파일이 한 몸이다

- `.xcdatamodeld` · `Generated/*+CoreDataProperties.swift` · `Tools/cloudkit/slowrich.ckdb`.
- **빠진 `@NSManaged` 선언은 컴파일을 통과하고 화면 값 하나가 조용히 빈다.** 그래서
  CI 의 대조 스크립트가 유일한 심판이다.
- **규칙.** 칸을 더하는 절차를 문서에 번호로 적어 두고(06) 그대로 따른다:
  모델 → 선언 → `generate-ckdb.py` → 체크 스크립트 → `Backup` 옵셔널 필드 →
  Development 적용 → **사람이 Production 배포**.

### Production 은 저절로 안 생긴다

- 저장 계층은 Development 에서만 레코드 타입을 자동 생성한다. TestFlight 는
  Production 을 쓴다. 엔타이틀먼트로 못 바꾼다. 맥이 없으면 Development 조차 비어
  있다.
- 해결: `CKTool JS` 는 Node 라 리눅스 러너로 충분하다. 워크플로가 `.ckdb` 를
  Development 에 밀어 넣고 사람이 콘솔에서 Deploy.
- **`cloudkit.share` 같은 시스템 타입도 같은 규칙이다.** 앱이 Development 에서 처음
  공유를 시도할 때 생기는데 그 일이 영영 안 일어난다. `.ckdb` 에 같이 뽑고 이름에
  점이 있어 따옴표로 감싼다.
- **모델을 고치면 다시 올린다.** 안 올리면 새 필드가 iCloud 에 안 가는데 화면에서는
  티가 안 난다. 옮기기 기능이 `Cannot create or modify field 'CD_moveReceipt' …
  in production schema` 로 막힌 것이 그 예다.

### 갈아탈 때 저장소 파일은 같은 것이어야 한다

- SwiftData 기본 경로 `Application Support/default.store`. 다른 경로를 열면 앱은
  멀쩡히 뜨는데 **빈 화면**이고, 사용자는 "몇 달치가 날아갔다" 를 본다.
- **규칙.** 경로를 못 박고, 엔티티 · 속성 이름을 그대로 쓴다(`.ckdb` 의 `CD_` 이름이
  증거). **옮기기 전에 백업 기능부터 만든다** — 40번 백업이 미리 값한 자리다.

### CloudKit 에는 "최댓값" 쓰기가 없다 — 견줘서 쓰는 칸은 가져온 뒤에 쓴다

- **사건.** 가구의 `latestBuild` 를 "로컬 값보다 내 빌드가 높으면 올려 적는다" 로
  했더니, TestFlight 가 뒤에서 올려 둔 아이패드가 켜지자마자 옛 로컬 값과 견줘 77 을
  적었고, 밀어 넣기의 충돌 해결("내가 바꾼 칸은 내 값")이 서버의 78 을 덮었다 (146번).
- **규칙.** 서버 값과 견줘 쓰는 칸은 이번 실행의 **첫 가져오기가 끝난 뒤**에만 쓴다.
  마지막에 쓴 기기가 이기므로, 견줄 값이 최신이라는 보장 없이 쓰면 낮은 값이 이긴다.

### 두 기기가 같은 사람을 다르게 부른다

- 참가자 기기에서 읽은 사용자 ID 가 자리표시였고 관리자 폰의 `editorIDs` 와 영영
  안 맞았다.
- **규칙.** 서로 견줄 ID 는 언제나 서버가 준 절대 이름(`fetchUserRecordID`)으로.
  진단 화면에 "ID 꼬리" 한 줄을 두면 동기화 지연으로 착각하는 한 바퀴를 아낀다.

### 뿌리를 새로 만들 때 "앞으로 만들 것" 과 "이미 있는 것" 을 따로 센다

- 새 레코드는 공유 존에 붙였는데 이미 개인 존에 올라간 레코드는 아무도 안 맡았다.
  두 기기가 있어야 보이는 실패라 **합격 기준을 먼저 적어 둔 것**이 유일한 그물이었다.

### 토큰에는 만료일이 있다 — 만들 때 달력에 적는다 (2026-09-28)

- CloudKit 관리 토큰을 2026-09-07 에 만들고 시크릿에 넣은 뒤 잊었다. 만료(10-06)는
  사용자가 콘솔에서 우연히 봤다. 다행히 스키마 워크플로만 쓰는 토큰이었다.
- **규칙.** 토큰 · 키를 시크릿에 넣을 때 **어디에 쓰는지, 언제 만료되는지**를 문서 한 줄과
  로드맵 일정 표에 함께 적는다. 만료되면 무엇이 멈추는지까지 적어 두면 급한지 아닌지가 바로 갈린다.

### 되돌릴 수 없는 서버 작업은 사람이 누른다

- 존 사이 옮기기는 서버에서 **삭제를 포함**한다. 화면에서 성공처럼 보여도 그렇다.
- **규칙.** 자동으로 돌리지 않는다. "먼저 백업을 받으셨나요?" → 한 기기에서만 →
  버튼 한 번.

### 참가자 기기에도 개인 저장소가 있다

- 참가자 폰에서 공유를 받기 전에 만든(또는 체험으로 생긴) 레코드가 개인 저장소에
  남아 화면에 섞였다. `deleteStrays()` 와 "개인 저장소의 기록 N건 지우기" 버튼으로
  풀었다.
- **규칙.** 공유 앱은 **역할별 저장소 상태**를 화면에서 볼 수 있게 한다.

### 더하기 전에 있는 것을 찾는다

"가족 대표를 정하는 칸" 을 요청받고 새 칸을 만들 뻔했다. 찾아보니 1페이지가
처음부터 "구성원 순서의 맨 위 사람" 을 가장으로 쓰고 있었고, 순서를 바꾸는
화면도 있었다. 띠지와 문구만 더해서 끝났다 — 스키마도, 새 화면도 없이.

규칙: **기능을 더하기 전에 같은 역할을 하는 것이 있는지 `grep` 으로 먼저
훑는다.** 있으면 이름을 붙이거나 표시를 더한다. 정하는 자리가 둘이 되면
어긋나고, 칸이 늘면 대조와 재배포가 따라온다. 검토 결과는 "있던 것 / 한 것"
표로 남겨 다음 사람이 같은 검토를 반복하지 않게 한다.

### 되돌리기는 같은 id 를 한 벌 더 만든다 — 정렬에 동점을 남기지 않는다

백업 되돌리기가 `id` 와 만든 시각을 그대로 베끼는 것은 맞다(스냅샷의 줄이
같은 사람을 가리켜야 한다). 그런데 옛 객체가 iCloud 를 거쳐 되돌아오면
**같은 id 의 객체가 둘**이 된다. 화면이 `createdAt` 하나로 정렬해 `.first`
를 쓰면 동점이고, 동점은 기기마다 다르게 풀린다 — 아이폰과 아이패드가
각자 다른 계획을 고치면서 "일부 필드만 동기화가 안 된다" 로 보였다. 원인을
세 번 잘못 짚고 나서, 두 기기의 저장소를 나란히 놓는 도구(엔티티별 해시 ·
레코드 id 꼬리)를 만들고서야 봤다.

규칙: **하나여야 하는 것은 정렬 규칙을 한 함수에 두고 화면 전부가 그것을
읽는다.** 동점 뒤에 고친 시각 · id · 객체 주소까지 이어 붙여 어느 기기에서든
같은 것을 고르게 한다. 그리고 "하나여야 하는 것이 둘" 은 화면에 빨갛게
띄우고 사람이 고르게 한다 — 앱이 골라 지우면 조용히 틀린 값이 남는다.

### 목록이 깜빡이면 자료가 아니라 목록의 낙관 동작을 본다 (178~182)

- **일어난 일.** "지울 때 뭔가 생겼다 없어진다" 를 여섯 빌드에 걸쳐 쫓았다.
  자료 쪽(지운 객체가 한 박자 더 그려짐)을 두 번 고쳤지만 원인이 아니었다.
- **원인.** SwiftUI 목록의 **낙관 동작**이 둘 있다 — `onDelete`, 그리고
  `role: .destructive` 를 준 미는 버튼. 둘 다 누르는 순간 **줄을 먼저 접고**
  자료가 따라오기를 기다린다. 확인 창을 먼저 띄우는 앱에서는 줄이 접혔다
  돌아오는 것으로 보인다.
- **규칙.** 확인을 먼저 받는 삭제는 `swipeActions` 의 **역할 없는** 버튼 +
  화면이 든 확인 창 한 장(`swipeDelete` · `confirmsDelete`) 으로 한다. 줄에
  붙는 것(`swipeActions`)은 `Group` 으로 감싸면 사라지고, 오래 살아야 하는 것
  (확인 창)은 줄이 아니라 화면이 든다.
- **잡은 방법.** 원격 세션은 움직임을 못 본다. **사용자의 화면 녹화를 ffmpeg
  로 60fps 프레임 대조표로 잘라 읽었다.** 같은 원인의 두 얼굴(아래 줄 깜빡임 ·
  선택한 줄 비움)이 두 영상에서 갈라져 보였고, 그것이 원인을 확정했다.
  움직임 버그는 녹화를 받는다 — 스크린샷으로는 못 잡는다.

### 안정화 기간에는 안 쓰는 화면을 일부러 연다 (2026-09-29)

- 주간 점검 · 목·실·감만 매일 쓰는 동안 "4주 무사고" 가 쌓였지만, 계획 탭 목돈을 처음 지우자
  죽었다(189번). 쓰는 화면만 쓰면 나머지는 검사된 것이 아니다.
- **규칙.** 안정화 기간을 시작할 때 **요일별 점검 루틴**을 정한다 — 매일 1분 공통 + 요일마다 한
  영역 + 날짜 경계(달 · 해가 바뀌는 날). 지운 · 취소는 테스트용 항목으로만.
  이 저장소의 판은 [14 매일 점검 루틴](14-daily-test-routine.md). 값을 했는지는 끝난 뒤 거기 적는다.

### 앱이 죽으면 크래시 로그부터

- `UICloudSharingController` 준비 핸들러가 메인에서 수백 건을 옮겨 iOS 가 앱을 죽였다.
  로그를 세 바퀴 늦게 요청했고 그동안 API 사용법을 추측으로 바꿨다. 둘은 새로 심은
  버그였다.
- **규칙.** 사용자에게 **설정 → 개인정보 보호 → 분석 데이터** 의 크래시 로그를 먼저
  받는다. 그다음에 고친다.
- **스스로 지우는 편집 시트는 지운 객체를 다시 그리다 죽는다 (189번).** 시트가
  내려간 순간 SwiftUI 가 본문을 한 번 더 그리고, 그 사이 자동 저장이 돌면 속성이
  전부 nil 이다. `String` 은 "" 로 넘어가 멀쩡해 보이고 `Date` · `UUID` 에서만
  죽는다 — 저장 타이밍에 따라 가끔만. 로그 한 장(`Date._unconditionallyBridgeFromObjectiveC`
  ← `Binding` ← `dismissalTransitionDidEnd`)으로 바로 짚였다.
  **규칙.** `context.delete(x); dismiss()` 를 하는 화면은 본문 맨 위에서
  `x.isGone`(삭제됨 또는 문맥 없음)이면 빈 화면을 그린다. 하나를 고치면 같은
  꼴을 전부 찾는다 — 이 저장소에는 여덟이 있었다.
  **본문 가드만으로는 모자란다 (빌드 113).** `DatePicker(selection: $obj.date)` 처럼
  연결을 쥔 칸은 본문이 안 불려도 그 연결을 따로 다시 읽는다. nil 을 못 받는
  칸(`Date` · `UUID`)은 `$obj.칸` 으로 묶지 말고 `Binding(get: { obj.isGone ? 기본값 : obj.칸 })`
  으로 묶는다. 저장된 적 없는 객체는 지우는 즉시 값이 비어서 더 빨리 드러난다.

  짝지어** 보여 준다.
- **다음 앱 규칙.** 여러 사람이 쓰는 앱에서 "그 주의 합계" 같은 파생값을 레코드로 저장한다면,
  처음부터 **원천에서 다시 만들 수 있게** 설계한다.

## 4. Swift 6 · SwiftUI 코드에서 반복된 것

### 동시성

- **`NSManagedObject` 를 `async` 경계 너머로 넘기지 않는다.** `Sendable` 이 아니다.
  Int · Date · Money 만 뽑아 `Sendable` 구조체로 건넨다. 세 번 밟고 세 번 다 값으로
  풀었다. `@preconcurrency` 로 검사를 끄지 않는다.
- `@MainActor` 함수를 nonisolated 에서 부르면 막힌다 → 정말 메인이 필요한지 묻고
  아니면 뗀다(`makeTrialContainer`).
- `onPreferenceChange` 클로저는 `Sendable` 이라 `@State` 를 직접 못 고친다 →
  `Task { @MainActor in … }`.

### Dynamic Type 은 첫날부터

- **사건.** 글꼴 275곳이 `.system(size:)` 였고, 큰 글씨 스크린샷이 보통과 바이트까지
  같았다. 고치고 나니 이번엔 **글자를 담는 칸**(폭 · 높이 · 여백)이 고정이라 캡션이
  겹치고 배지가 줄 바꿈됐다.
- **규칙.**
  - 글꼴은 `Font.scaled(_:weight:)` 하나로. 숫자는 `Font.figure` (tabular · 우측 정렬).
  - 글자를 담는 길이는 `Font.scaledLength(_:)`. 종이(PDF)만 예외.
  - 배지 · 짧은 라벨: `lineLimit(1)` + `fixedSize`.
  - 범례 · 표: `ViewThatFits` 로 가로 → 세로 · 가로 스크롤을 준비한다.
  - 세로 축 텍스트필드(`axis: .vertical`)는 `.top` 정렬 (`.firstTextBaseline` 이 어긋난다).
  - CI 스크린샷에 **큰 글씨 한 장**을 넣어 증명한다.

### 핀치 줌은 UIKit 으로

- SwiftUI 만으로 세 바퀴 돌았다: 프레임이 측정값×배율을 다시 제안해 **레이아웃
  되먹임**으로 iPad 가 멈춤 → `.gesture` 가 `ScrollView` 에 먹힘(`.simultaneousGesture`
  로 잠시) → 그래도 툭툭 끊김.
- **규칙.** 확대 · 축소 · 관성은 `UIScrollView` 를 `UIViewRepresentable` 로 싼다.
  내용은 2× 로 그리고 `fixedSize`, 폭 맞춤 배율을 최소로, 그 4배를 최대로.
  **`transform` 이 걸린 뷰에 frame 을 주면 초기 위치가 어긋난다** — 자연 크기가
  바뀔 때 다시 맞춘다.

### 키보드 툴바는 믿지 않는다 — 키보드 위의 띠는 화면 안에 그린다

- **사건.** 주간 점검의 `만 · 억 · 변동 없음 · 다음` 을 `placement: .keyboard` 툴바에
  뒀더니, 늦게 만드는 목록(`LazyVStack`)에서 커서가 줄 사이를 오갈 때 툴바가 붙었다
  떨어졌다 했다. 떨어진 자리에 iOS 의 `자동 완성` 알약이 대신 떴고, 글자 크기를
  바꿔도 다시 그려지지 않았으며, 좁아지면 `1 / 14` 를 세 줄로 꺾었다 (144번).
- **규칙.** 키보드 위에 늘 있어야 하는 도구는 `.safeAreaInset(edge: .bottom)` 으로
  화면 안에 그린다. 키보드가 올라온 만큼 위로 밀려 늘 키보드 바로 위에 있고, 포커스가
  없으면 숨긴다. 숫자는 `lineLimit(1)` + `fixedSize` 로 한 줄에 못 박는다.
- 늦게 만드는 목록에서 **화면 밖 줄에 바로 포커스를 주면 안 온다.** 스크롤해 만든 뒤
  잠깐 기다렸다가 준다 (107 · 144번).

### "다녀간 줄" 은 닿은 줄이 아니라 떠난 줄이다

- **사건.** "다시 열면 안 적은 줄부터" 를 만들며 커서가 **닿은** 줄을 기록했더니,
  열 때 저절로 앉는 줄까지 다녀간 줄이 되어 다시 열면 그 줄을 건너뛰었다. 첫 판은
  `lastEnteredAt` 으로 가렸는데, 점검을 끝내는 순간 큐 전체에 시각이 찍혀(변동 없음도
  기록이다) 늘 맨 위였다 (144-C, 두 번 고침).
- **규칙.** 진행 상태는 **사용자의 동작**(떠남 · 다음 · 완료)으로 정의하고, 자료의
  시각 칸을 진행 표시에 겸용하지 않는다. 기기 편의(커서 위치)는 자료가 아니므로
  `UserDefaults` 에 두고 iCloud 로 보내지 않는다.

  2026-09-12 실기기에서 확인해 날짜를 적었다.

### 값의 출입구는 하나로

- **사건.** 평가액을 주간 점검 · 자산 탭 편집 · 지난 값 되돌리기 세 곳에서 고칠 수
  있었다. 셋 다 기준값 규칙과 이력은 지켰지만, 자산 탭에서 고쳐도 "이번 주 적었다" 가
  찍혀 점검 큐 · 진행 · 연속 기록의 뜻이 흐려졌다. 사용자가 먼저 정책을 제안했다 (145번).
- **규칙.** 같은 값을 고치는 길이 둘 이상이면 **하나를 정문으로** 정하고 나머지는
  정문으로 보내는 버튼만 둔다 (`이번 주 점검에서 고치기`). 예외는 정문이 닿지 않는
  경우(첫 값 · 점검 큐에 안 오는 `고정` 주기)만 명시적으로 남긴다. 편집 가능 여부는
  **열 때** 정한다 — 첫 값을 치는 순간 "적었다" 가 찍혀 칸이 잠기면 두 번째 자리부터
  못 친다.

## 5. 사용자 자료 — 한 번 잃으면 끝

- **실제 금액 · 기관명 · 계좌를 커밋하지 않는다.** 사용자가 보내는 화면 캡처에는
  실제 금액이 있다. 문서에 옮길 때는 지어낸 숫자로 바꾼다. 스토어 스크린샷은 체험
  자료로 찍는다.
- **백업 · 되돌리기를 큰 변경 전에 만든다.** 갈아타기 · 옮기기 · 공유 전부 백업이
  먼저 있었기에 되돌아갈 길이 있었다.
- **체험 자료는 메모리 컨테이너에.** 실제 저장소에 씨앗을 뿌리면 동기화 자료와 섞인다.
  `TrialMode` 가 별도 컨테이너를 들고 `viewContext` 를 갈아 끼운다. 체험 중 배너 하나
  ("체험 자료입니다 · 실제 금액이 아닙니다")를 항상 띄운다.
- **모든 삭제에 확인 장치** (16번). "전부 지우기" 는 문구를 타이핑하게 한다.
- **"데이터가 사라진 적이 없다" 4주 시계**는 되돌릴 수 없는 작업을 한 날부터 다시
  센다.

## 6. 계산 — 기댓값을 지어내지 않는다

- 컴파일 못 하는 환경에서 테스트 기댓값을 손으로 적으면 **테스트가 버그를
  승인**한다. 복리 테스트 오류를 파이썬 대조로 잡았고, 국민연금 추정(125번)도
  A값 · 상한 · 하한 · 최소 가입 개월을 파이썬으로 계산한 값만 넣었다.
- **규칙.** 수치 기댓값은 다른 언어 · 다른 방법으로 한 번 더 계산해 1원까지 맞춘 뒤
  적는다. 테스트 커밋 메시지에 "기댓값은 파이썬으로 대조" 라고 남긴다.
- 같은 입력에 두 결과(63번)가 나오면 **어느 쪽이 맞는지**를 독립 계산으로 먼저
  정한다. 둘을 같게만 만들면 둘 다 틀릴 수 있다.

## 7. 스토어 준비 — 테스트하는 동안 미리

- **개인정보 처리방침 URL 은 첫 빌드 전에.** GitHub Pages 로 **방침만** 낸다
  (`/docs` 전체를 내면 설계 문서가 다 공개된다 → `Tools/site/build.py` 가 한 장만
  만든다). App Store Connect 에서 입력하는 곳은 `App Store → 앱이 수집하는 개인정보`
  이지 앱 정보가 아니다.
- **스크린샷 크기.** iPhone 칸이 6.9" 만으로는 안 받고 **6.5"(1284×2778 또는
  1242×2688)** 를 요구했다. iPad 는 13"(2064×2752). CI 워크플로가 Pro Max · iPad Pro 로
  찍고 캡션을 얹어 두 크기를 다 만들어 둔다.
- **상표 검색(KIPRIS)** 을 이름 정할 때 한 번 한다.
- **"1위" 의 뜻을 먼저 정한다.** 검색 1위 · 평점 · 에디터 추천처럼 잴 수 있는 것으로.
  부제 · 키워드 · 설명은 그 목표에서 나온다(10). 출시 날짜를 정하면 준비 목록이
  저절로 잘린다.
- **후기 요청은 기분 좋은 순간에, 90일에 한 번, 체험 중엔 안 한다.**
- **"새 판이 나왔습니다" 는 첫 스키마에 넣는다.** 빌드 74까지 업데이트 안내가
  없었다(143번). 서버가 없으면 가족이 나눠 쓰는 뿌리 레코드에 **가장 높은 빌드
  번호**를 적는 것이 유일한 신호인데, 그 칸이 없던 판은 영영 안내를 못 받는다.
  뒤늦게 넣으면 그 전 판 사용자에게는 말로 알려야 한다.
  **App Store 를 열면 TestFlight 판은 그 번호를 적지 않는다** (2026-10-03). 부모는 TestFlight 로
  더 새 빌드를 먼저 받고 아이들은 App Store 판을 쓰는데, TestFlight 번호가 가구에 적히면 아이들 폰에
  "새 버전" 띠가 사라지지 않는다 — App Store 에는 아직 그 판이 없다.
- **아이(어린) 계정은 TestFlight 에 못 들어온다** (2026-10-03). 테스터 나이 제한이 있다. 가족 앱이라
  아이들까지 시험하려면 **App Store 로 낼 수밖에 없다.** 느린 여백에서 아이들 폰까지 깔아 보니
  오류를 훨씬 많이 찾았다 — 다음 앱은 "가족 전원 시험" 을 출시 계획에 처음부터 넣는다.
- **이름을 바꾸면 스토어 스크린샷을 다시 찍는다** (2026-10-03). 09-12 판 첫 장 머리글에 옛 이름
  `느린 부자의 기록` 이 남아 있었다 — 제출 직전에야 봤다. 메타데이터가 실제 앱과 다르면 2.3 반려다.
- **제출 시트를 한 장 만든다** ([15](15-app-store-submission-sheet.md)). App Store Connect 화면 순서대로
  칸마다 붙일 값과 ☐. 이미 넣은 칸도 "처음 쓴다" 고 보고 대조하니 심사 메모의 사실 오류 둘(메뉴 이름 ·
  고지 위치)이 나왔다. **수동 출시** 를 고르면 통과해도 버튼을 누를 때까지 공개되지 않아 마음이 편하다.

## 8. Claude 와 일하는 방식 — 이게 제일 많이 아꼈다

- **문서가 코드보다 앞선다.** 헷갈리면 `docs/` 를 먼저 읽는다. `CLAUDE.md` 에 규칙과
  "기억해 둘 것" 을 두고, 세션이 바뀔 때마다 그것을 기억으로 쓴다.
- **이슈는 번호 · 상태 · 빌드 번호.** 🔴🟡🔵🟢🟠 다섯 상태. 뒤엎은 것(🟠)은 어느
  항목이 대신하는지 적는다. 사용자는 "1~7 확인 완료" 로만 답해도 된다.
- **가정 표.** 확인 안 된 가정을 A1… 으로 적고 확인한 날짜를 채운다. 로드맵의
  "1.0 안정화 판단 기준" 도 같은 꼴이다.
- **빌드마다 체크리스트 + 사용자가 할 일.** 앱 안에서 확인할 것과 콘솔 · 사이트에서
  할 것을 나눈다.
- **크래시 로그 · 진단 정보 · ID 꼬리**처럼 사용자가 **복사해 붙일 수 있는 것**을
  앱에 넣는다. "동기화가 안 돼요" 를 한 바퀴에 끝낸다.
- **사용자가 두 번 "확인해줘" 하면 러너 탓으로 돌리지 않는다.** 따옴표 사건, 핀치 줌
  사건 다 그랬다.
- **끝난 뒤 회고를 문서로 남긴다.** 이 문서다.

## 10. 출시 뒤 2주 — 남의 폰에서 도는 앱 (2026-10-04 ~ 10-17)

10-07 App Store 공개 뒤로 가족 밖 사용자가 생겼다(10-16 앱 분석: 판매량 11 · 업데이트 39). 그때부터 버그는
"우리 집에서 불편" 이 아니라 **"모르는 사람의 자료가 틀린다"** 가 됐다. 이 기간에 App Store 에 판을 네 번 냈다
(1.0.4 · 1.0.5 · 1.0.6 · 1.0.8(10-19) 공개 — 1.0.1 ~ 1.0.3 · 1.0.7 은 TestFlight 로만).

### 체크리스트는 코드에서 확인한 뒤 준다 (10-09)

- **사건.** 하루에 체크리스트가 세 번 틀렸다 — "생년 목록"(화면 이름은 `태어난 해`), 연속 기록이 있으면 안 보이는 문구,
  앱에 없는 "지난 점검 완료 화면 열기". 사용자는 없는 단추를 찾느라 시간을 썼다.
- **규칙.** 항목마다 코드에서 ① 그 화면 · 단추 · 문구가 있는지 ② **화면에 보이는 이름 그대로의 전체 경로**
  ③ **보이는 조건**을 확인하고 적는다. 확인 못 한 것은 넣지 않는다. CLAUDE.md 최상단 원칙이 됐다.
  조건이 까다로운 항목(30% 넘게 바뀐 값 · iCloud 로그아웃 기기 · 11-01)은 "건너뛰어도 된다" 를 함께 적는다.

### 사용자가 보낸 화면 사진의 숫자도 실제 금액이다 (194 P3)

- **사건.** 사진에서 옮긴 표와 금액 몇 개가 public 저장소 문서에 들어가 있었다. 고쳐도 git 이력에는 남는다.
- **규칙.** 사진의 숫자는 문서에 옮길 때 **예시로 바꾼다.** 건수 · 크기 · 날짜만 옮긴다(197 진단 정보처럼).
  이력까지 지우는 것(강제 푸시)은 사용자가 정한다.

### 출시 뒤 전수 조사는 관점을 나눠서 (194 · 199)

- **사건.** 기능 동결 중이라 "쓰면서 걸린 것" 만 고쳤는데, 관점을 정해 훑자 쓰는 사람이 안 밟는 자리에서 크래시 · 틀린 숫자가 나왔다:
  기기 달력이 **일본력이면 구성원 편집을 여는 순간 죽음**(연도 목록 `1930...8`), 공유 시트 `이미지 저장` 에서 죽음(사진 권한 문구 없음),
  **11-01 회고 알림이 빈 11월을 엶**, 국민연금 추정이 가입 20년 미만이면 최대 2배, 시뮬레이션 확률이 대출을 지워 부풀려짐.
- **규칙.** 관점을 나눈다 — **틀린 숫자 · 개인정보 · 날짜 · 처음 쓰는 사람**(194), **안정성 · 편의성**(199). 찾은 것은
  A 자료 어긋남(동결 예외) / B 틀린 숫자 / C 편의성 / D 드문 것(관찰) 으로 나누고 항목마다 `확인`(직접 · 조사 · 추정)과 코드 자리를 적는다.
- **판은 단계별로.** 1.0.1 고침 → 1.0.2 자료 지키기 → 1.0.3 계산(화면 숫자가 바뀐다 — 미리 알린다) → 1.0.4 처음 쓰는 사람.
  한 단계 = 한 빌드 = 한 체크리스트라 어느 단계 문제인지 가를 수 있다. App Store 에는 모아서 한 번에 낸다.

### 날짜 · 달력 — 기기 설정과 시간대를 믿지 않는다 (194 D · 199 B3)

- **달력.** `Calendar.current` 는 기기 달력을 따른다. 일본력이면 올해가 `8`, 불기면 `2569` — 나이 585세가 CloudKit 으로 가족에게 퍼졌다.
  → 앱 전체가 `Calendar.app`(그레고리력 · 기기 시간대 · 한국어 로케일) 하나로 센다. 예외는 알림 트리거에 넘길 숫자뿐(트리거가 기기 달력으로 읽는다).
- **시간대.** 주 기준일은 "그 기기의 토요일 자정" 인데 같은 주를 시각 `==` 로 찾아, 해외에서 점검하면 같은 주가 둘로 갈렸다.
  → **날 번호**(`ReviewWeek.dayKey` — 기준일 + 13시간의 UTC 날짜)로 견준다. 처음엔 +12시간이라 뉴질랜드 여름(UTC+13)에서 하루 어긋났다 —
  시간대 경계는 **양 끝(UTC−10 · +13)을 시험에 넣는다.**
- **경계일.** 11-01 회고 · 달이 바뀐 첫 주의 `이번 달` · 1월 1일 `올해 납입액`. 경계일마다 "그날 화면에 뭐가 나오나" 를 표로 적어 보면 나온다.
- **해가 바뀌면 0 이 되는 값.** 01-01 에 값을 0 으로 지우면 여러 기기가 서로 덮어쓴다 → 값은 두고 **"몇 년 값인지" 칸**(`annualContributionYear`)을 더해
  그해 것만 센다. 칸이 없던 판의 값(0)은 "그 판의 해" 로 본다.

### 화면이 다시 만들어지면 `@State` 는 처음으로 돌아간다 (199 C4 · A1)

- **사건.** 아이패드를 돌리면 점검 창이 닫혔다. 가로(사이드바) · 세로(탭)를 `if` 로 갈랐더니 SwiftUI 에게는 **다른 화면**이라 돌리는 순간
  `TabView` 와 그 안의 현황판이 새로 만들어졌고, 창을 띄우던 `@State` 가 닫힘으로 돌아갔다. 미리 보기 녹화에서 `-startReview` 창이
  열렸다 닫혔다를 되풀이한 것도 같은 까닭이었다.
- **규칙.** 전체 화면 창은 **분기 바깥(루트)** 에 달고, 여는 신호는 앱 경로 객체(`AppRoute`)에 둔다. "열 때 값 · 이 기기가 쓴 값" 처럼
  창이 끝날 때 필요한 장부도 화면 `@State` 가 아니라 **화면 밖 객체**(`ReviewLedger`)에. 화면이 다시 만들어져도 잃지 않는다.
- **남은 것.** 다른 탭의 편집 시트는 아직 돌리면 닫힌다 — 다음 앱은 처음부터 **탭 구조를 크기에 따라 가르지 않는다**(`TabView` 하나에 스타일만 바꾸기).

### 입력칸은 사라질 때도 쓴다 (199 A2 · A3 · A4 · 빌드 127)

- **사건.** 커서가 금액 칸에 있는 채 `취소` 하면 **친 값이 저장됐다** — 시트가 닫히며 칸이 `onDisappear` 에서 적던 글자를 넣었다(되돌린 뒤에).
  고친 1.0.6 첫 빌드(127)에서도 점검 `나중에 → 되돌리고 나가기` 가 커서 줄의 값을 남겼다 — 창이 내려가는 동안 `TextField` 가
  들고 있던 글자로 세터를 **한 번 더** 불렀다. 반대로 키보드를 둔 채 `저장` · 앱 내리기를 하면 마지막 글자가 **빠졌다**.
- **규칙.** 금액 칸 하나에 문 둘 — `commitActive()`(지금 쓴다: 저장 · 앱이 `.inactive` 로 갈 때)와 `discardActive()`(버린다: 취소 · 되돌리기).
  되돌리는 창은 **닫는 동안 세터를 막는다**(`isClosing`). 퍼센트 손잡이의 250ms 늦은 쓰기도 취소 뒤엔 안 쓴다.
  확인은 늘 **"커서를 둔 채로"** 한 번 더.

### 여러 기기 — 되돌리기는 "이 기기가 쓴 것" 만 (194 E1 · 199 A1 · A5 · A6)

- **되돌리기.** 편집 `취소` · 점검 `나중에` 가 "열 때 값" 으로 되돌리면, 그 사이 다른 기기에서 내려온 가족의 값까지 지운다.
  → 이 기기가 쓴 값을 기억하고(`written`), **지금 값이 그것과 같은 줄만** 되돌린다.
- **판정 시점.** 새로 깐 참가자 폰이 "가져오기 끝" 을 개인 저장소(거의 비어 빨리 끝남) 기준으로 보고 잠깐 관리자로 저장했다.
  → 역할 판정 · 합계 재계산은 **공유 저장소 가져오기가 끝난 뒤**(`hasFinishedSharedImport`).
- **중복 정리의 승자.** 기기마다 다른 쪽을 남기면 둘이 서로 지워 그 주가 통째로 사라진다 → 정렬 끝에 **id · 레코드 이름**까지 두어 모든 기기가 같은 답(§3).

### iOS 26 확인 창은 `.cancel` 단추를 감춘다 (199 C1 · 200)

- **사건.** `confirmationDialog` 가 말풍선(popover)으로 뜨면 `role: .cancel` 단추를 그리지 않고 바깥 누르기로만 닫는다.
  `계속 적기` 가 안 보였고(빌드 127), 삭제 확인 창에 `취소` 가 없었다(빌드 129). 두 번 다 시뮬레이터 스크린샷에는 안 나온다.
- **규칙.** 확인 창의 취소는 **역할 없는 이름 있는 단추**(`Button("취소") {}`)로. `grep "role: .cancel"` 이 0 이어야 한다.

### 잠금 화면 — 앞에 있을 때만, 한 번만 묻는다 (194 P1 · 195)

- 잠금을 루트의 겹친 층으로 두면 시트 · 전체 화면 창이 그 **위에** 뜬다 → 잠금은 별도 창으로.
- 그러자 창이 백그라운드로 내려가는 순간 Face ID 를 물어 `LAError.notInteractive` 가 "인증에 실패했습니다" 로 보였다.
  → 자동으로 묻는 것은 **앱이 앞에 있을 때, 잠길 때마다 한 번만**. `notInteractive` 는 오류로 보이지 않는다.
- 가리기(금액 숨김)는 같은 문구를 그리는 **모든 자리**를 grep 한다 — 점검 완료 화면만 고치고 회고 카드의 같은 축하 줄이 남았다.

### 모델 판 쌓기 · 마이그레이션 시험 (197 · 18 · 199)

- **물음.** 판이 하나뿐인데 칸을 더해도 왜 안 죽었나 → SQLite 가 마지막 모델 사본(`Z_MODELCACHE`)을 들고 있어서. **보장된 동작이 아니므로**
  CI 에서 출시한 판들의 저장소를 지금 모델로 열어 보는 시험으로 확정하고, 막는 검사로 바꿨다.
- **판을 쌓을 때 함정.** 대조 스크립트가 판 경로를 박아 두면 새 판을 쌓는 순간 **옛 판을 대조**한다 → `.xccurrentversion` 을 읽게.
  마이그레이션 시험이 기준 커밋에서 1판 폴더만 꺼내, 현재 판이 2판인 커밋(1.0.6)에서 모델을 못 열었다 → **모델 폴더를 통째로** 꺼낸다.
- **저장소를 저절로 지우거나 새로 만드는 코드는 넣지 않는다.** 못 열면 멈추고 알리는 안내 화면(저장소 · 관리 객체를 하나도 안 쓰는 별도 화면).

### 업데이트 안내 띠 — 적을 기기가 없을 수 있다 (198)

- 가구에 "최신 빌드" 를 적는 것은 App Store 판 · 편집 가능 기기뿐인데, 이 집은 부모 TestFlight · 아이 보기 전용이라 **적을 기기가 하나도 없었다.**
  진단 정보의 `가족 최신 빌드: 119` 로 찾았다. 신호를 "누가 적나" 까지 그려 보고, 각 기기가 스스로 아는 방식도 후보로 둔다.

### 스토어 자산 — 칸이 요구하는 크기는 화면에서 확인한다 (10-03 · 10-12 · 10-13)

- 스크린샷: 6.9"(1320×2868)는 거절, 6.5"(1284×2778)를 받았고, 미리 보기를 올린 15.5 · 15.9cm 칸은 **1206×2622 만** 받았다. 문서 · 기억이 아니라
  **App Store Connect 의 칸을 보고** 크기를 정한다. 포스터 프레임(정지 화면)도 **스크린샷 칸 크기**여야 한다.
- 미리 보기 녹화(`simctl recordVideo`)는 **가변 프레임** — 화면이 멈춘 동안 프레임을 건너뛰어 장면 표시와 수십 초 어긋나고, 입력 앞 `-ss` 로 자르면
  0.6초 밀려 끝에 홈 화면이 비쳤다(사용자가 찾음). → 처음부터 풀어 `fps=30,trim=` 으로 자른다. CI 에는 LLDB 가 없어 UI 테스트 스킴은 `debugEnabled: false`.
- 아이패드 시뮬레이터에서 UI 테스트로 연 점검 창이 저절로 닫혔다 — 위의 `@State` 문제였다. **녹화 이상도 앱 버그일 수 있다.**

### 버전 번호 — 제출 전에는 바꿀 수 있다 (10-09 · 10-17)

- TestFlight 로만 지나간 번호(1.0.1 ~ 1.0.3, 1.0.7)는 건너뛰어도 된다. App Store 버전 페이지 번호 = 빌드의 버전이어야 빌드를 고를 수 있고,
  **제출 전이면 페이지 번호를 고칠 수 있다** — 1.0.7 을 내지 않고 고친 것까지 1.0.8 로 합쳐 냈다.
- 공개된 번호로는 새 빌드를 못 올리므로, **심사 중에 다음 빌드를 만들 때는 번호부터 올린다.**
- 새로운 기능 글은 "직전 **공개** 판 대비" 로 쓴다 — 건너뛴 판의 내용까지 넣는다(1.0.8 은 1.0.6 대비).

### 일하는 방식 — 기억은 문서, 날짜는 예약 알림

- "하기로 했는데 안 한 일" 점검을 두 번 했고, 두 번 다 잊힌 것이 나왔다(날짜가 지난 예약 알림, 사실과 어긋난 상태 표). 08 "지금 상태" 와 로드맵 "출시 일정" 이
  세션을 넘는 기억이고, 날짜가 있는 일(11-01 확인 · 12-01 새 빌드 · 12-21 에디터 추천 · 01-11 2.0)은 **예약 알림**으로 넘긴다.
