# 5. 로드맵 · 리스크

## 마일스톤

기간은 **주말·저녁 시간 기준의 1인 개발** 가정입니다. 각 단계 끝에 실제로 쓸 수 있는
빌드가 나오는 것을 원칙으로 합니다.

### M0 — 스캐폴딩 (1주)
- Xcode 프로젝트 + 로컬 SPM 패키지 골격 (`Core`, `Persistence`, `DesignSystem`, `Features`)
- SwiftData 스키마 v1 + 인메모리 컨테이너 테스트
- CloudKit 컨테이너 설정, 기기 2대 동기화 확인
- `Money` / `Quantity` 값 타입 + 포맷터 + 테스트
- **검증 과제**: 스케일드 정수가 CloudKit 왕복에서 정확히 보존되는지 확인 (→ ADR-0003)
- CI: `Core` 패키지 테스트 자동 실행

### M1 — 입력과 현황 (2~3주) ★ 첫 실사용
- 구성원 / 계좌 / 보유 자산 CRUD
- 평가 방식 3종(자동 시세 / 수동 단가 / 평가액 직접)
- **연속 입력 모드**
- 현황판: 총자산, 구성원 카드, 자산군·지역 비중
- 일별 스냅샷 기록
- CSV 가져오기 (기존 스프레드시트 이관)
- ✅ **완료 기준: 기존 1페이지의 "현재" 부분을 앱으로 대체할 수 있다**

### M2 — 궤적과 예측 (2~3주) ★ 이 앱의 정체성
- 적립 계획 / 연금 / 목돈 이벤트 입력
- 결정론적 프로젝션 엔진 + 테스트
- 순자산 궤적 차트 (과거 실선 + 미래 점선)
- 로드맵 타임라인 + 마일스톤(수동 + 자동 판정)
- 실질/명목 토글
- ✅ **완료 기준: 1페이지의 성장 궤적을 앱이 자동으로 그린다**

### M3 — 시뮬레이션 (1~2주)
- 몬테카를로 + 신뢰구간 밴드, 목표 달성 확률, 고갈 나이
- What-if 슬라이더 (드래그 중 결정론 / 놓으면 몬테카를로)
- 시나리오 저장·비교
- ✅ **완료 기준: 월 적립 50만원 증가의 효과를 3초 안에 확인할 수 있다**

### M4 — 점검 (1~2주)
- 운용 원칙 CRUD + 자동 점검 엔진
- 세적(PFIC) 제약 경고, 계좌 한도 게이지
- 유의사항·할 일 + 기한 로컬 알림
- 현황판 경고 스트립
- ✅ **완료 기준: 분기 점검을 앱 안에서 끝낼 수 있다**

### M5 — 마감 (1~2주)
- 시세·환율 자동 갱신, 다중 통화
- Face ID 잠금, 금액 가리기
- 1페이지 PDF/이미지 내보내기
- CSV 내보내기, 온보딩 흐름, 빈 상태 화면
- 접근성 점검, 한국어 문자열 정리
- ✅ **완료 기준: 가족에게 보여줄 수 있다**

### M6 — 출시
- TestFlight 내부 테스트, 개인정보 처리방침, App Privacy 신고
- App Store 심사 대응 (금융 카테고리 고지 문구 확인)

### 이후
위젯 → 배우자 실시간 공유(CloudKit shared DB) → 리밸런싱 제안 →
국내 시세 연동 → 세금 반영 → iPad/Mac

## 검증이 필요한 가정

설계를 확정하기 전에 M0에서 직접 확인해야 하는 것들입니다.

| # | 가정 | 확인 방법 |
|---|---|---|
| A1 | SwiftData + CloudKit이 이 스키마 규모(12개 모델, 다대일 관계 다수)에서 안정적이다 | M0에서 실기기 2대 동기화 테스트 |
| A2 | 스케일드 `Int`가 CloudKit 왕복에서 손실 없이 보존된다 | M0 왕복 테스트 |
| A3 | 몬테카를로 1,000경로 × 30년(360스텝)이 아이폰에서 200ms 이내 | M0에서 프로토타입 벤치마크 |
| A4 | 사용 가능한 무료 시세 API가 있고 약관상 개인 앱 사용이 허용된다 | 후보 3곳 약관 확인 |
| A5 | 연속 입력 모드로 자산 30건 갱신이 2분 이내에 끝난다 | M1 완료 후 실측 |

## 리스크

### R1 — SwiftData + CloudKit 제약 (영향 高 / 가능성 高)
CloudKit 미러링을 켜면 `@Attribute(.unique)` 사용 불가, 모든 속성에 기본값 필요,
모든 관계가 옵셔널이어야 합니다. 나중에 켜면 스키마를 뒤엎어야 합니다.

**대응**: 처음부터 제약을 지킨 스키마로 설계하고 M0에서 실기기 동기화를 확인합니다.
유일성은 앱 레벨에서 보장합니다. → [ADR-0001](adr/0001-swiftdata-cloudkit.md)

### R2 — 국내 주식 시세 소스 부재 (영향 中 / 가능성 高)
국내 상장 종목의 안정적인 무료 시세 API가 사실상 없습니다.
비공식 엔드포인트는 약관 위반 소지와 예고 없는 차단 위험이 있습니다.

**대응**: v1은 국내 종목을 수동 입력으로 두고, 이를 **결함이 아니라 설계**로 다룹니다
(연속 입력 모드가 그래서 중요합니다). 사용자가 자기 API 키를 넣을 수 있는 경로를 열어 둡니다.

### R3 — 예측의 신뢰성 (영향 高 / 가능성 中)
연 8% 복리로 23년을 그리면 숫자가 매우 커집니다. 사용자가 이를 **약속으로 받아들이면**
잘못된 재무 결정으로 이어질 수 있습니다.

**대응**: 신뢰구간 밴드를 기본으로 보여주고(단일 선이 아니라), 실질가치 토글을 눈에 띄게 두고,
모든 예측 화면에 고지 문구를 둡니다. 보수 시나리오를 기본 시나리오와 나란히 보여줍니다.

### R4 — 입력 부담으로 인한 이탈 (영향 高 / 가능성 中)
자동 연동이 없으므로 사용자가 손으로 넣어야 합니다. 이것이 이 앱의 가장 큰 이탈 요인입니다.

**대응**: 연속 입력 모드(S2)를 M1에 넣고 실측합니다(A5). 시세 자동 자산은 아예 손대지 않게 하고,
"마지막 갱신 후 N일" 을 표시해 무엇만 고치면 되는지 즉시 알게 합니다.

### R5 — 개인 금융 데이터 유출 (영향 極大 / 가능성 低)
가족 4인의 자산·계좌·세적 정보가 담깁니다.

**대응**: 서버를 두지 않는 것이 1차 방어입니다. 앱 잠금, 앱 전환기 블러,
릴리즈 빌드 로깅 금지, 크래시 리포트 제외를 M5에 포함합니다.
**저장소(GitHub)에도 실제 금액·기관명을 커밋하지 않습니다** — 테스트 픽스처는 가상 데이터를 씁니다.

### R6 — 규제 경계 (영향 中 / 가능성 低)
투자 추천이나 수익 보장으로 해석될 여지가 있으면 문제가 됩니다.

**대응**: 앱은 사용자가 입력한 가정을 계산만 합니다. 종목·상품을 제안하지 않습니다.
세무 관련은 기한 알림까지만 하고 세액을 확정 계산하지 않습니다.

### R7 — 범위 팽창 (영향 中 / 가능성 高)
가계부, 리밸런싱, 세금 계산, 자녀 교육비, 부동산 시세… 넣고 싶은 것이 계속 생깁니다.

**대응**: 모든 기능 제안을 *"기존 1페이지를 더 잘 만들어 주는가?"* 로 판정합니다.
[Non-goals](01-product-spec.md#18-범위-밖-non-goals) 목록을 실제로 사용합니다.
