# 실기기 피드백 — 고칠 것

TestFlight 로 아이폰에 올린 뒤 실제로 쓰면서 나온 것들을 모은다.
시뮬레이터 스크린샷으로는 안 보이던 문제가 여기 쌓인다.

한 건씩 바로 고치지 않고 **모아서 한 번에** 고친다. 빌드 한 번에 여러 개를
확인하는 편이 왕복이 적다.

| 상태 | 뜻 |
|---|---|
| 🔴 | 아직 손대지 않음 |
| 🟡 | 고치는 중 |
| 🟢 | 고쳐서 올림 (빌드 번호 표기) |

---

## 🔴 1. 다크 모드에서 화면마다 톤이 제각각이고 글자가 안 보인다

**증상** (2026-09-06, 빌드 12)

기기 설정이 다크인데 화면마다 밝기가 다르다. 현황판은 밝고, 자산·계획·더보기는
어둡고, 시뮬레이션은 회색이다. 어두운 화면에서는 글자가 잘 보이지 않는다.
화면뿐 아니라 메뉴(탭 바·내비게이션 바)도 마찬가지다.

**원인**

앱은 시스템 설정을 그대로 따른다 (`preferredColorScheme` 을 지정한 곳이 없다).
그런데 `App/DesignSystem/Palette.swift` 의 색이 **전부 라이트 모드용 고정 hex** 다.
1페이지 계획서 PDF 에서 뽑은 값이라 라이트에서만 성립한다.

그래서 화면이 배경을 어떻게 칠하느냐에 따라 세 갈래로 갈린다.

| 화면 | 배경 처리 | 다크 모드에서 보이는 모습 |
|---|---|---|
| 현황판 · 주간 점검 · 1페이지 · 환영 | `.background(Color.white)` | **밝게** 남는다. 글자(`.ink`)는 읽힌다 |
| 자산 · 계획 · 할 일 · 지난 기록 | 배경을 안 칠함 → 시스템 배경 | **어둡다.** 글자가 `.ink`(거의 검정)라 **안 보인다** |
| 시뮬레이션 · 자산 진단 | `Color.surface.opacity(0.5)` | 밝은 회색이 어두운 배경에 겹쳐 **회색**이 된다 |
| 탭 바 · 내비게이션 바 | 시스템 기본 | 어둡다 — 본문과 어긋난다 |

고정 색 사용처는 `Palette.swift` 를 빼고 231곳이다.

```
.ink 75 · .muted 52 · .faint 49 · .rule 27 · Color.white 13 · .bodyText 8 · .surface 4 · .ruleStrong 2
```

**고칠 방향**

1. `Palette.swift` 의 토큰을 **적응형**으로 바꾼다. 지금 값을 라이트 쪽에 그대로
   두고 다크 쪽 값을 짝지어 준다 (`UIColor(dynamicProvider:)` 를 `Color` 로 감싼다).
   색을 쓰는 231곳은 손대지 않아도 되게 — 토큰 이름을 그대로 유지한다.
2. 화면 배경으로 쓰인 `Color.white` 13곳을 의미 있는 토큰(`Color.canvas` 같은)으로
   바꾼다. "흰색"이 아니라 "바탕"이어야 다크에서 따라온다.
3. `Color.surface.opacity(0.5)` 처럼 **불투명도로 만든 회색**을 걷어낸다.
   겹쳐지는 배경이 무엇이냐에 따라 결과가 달라져서 두 모드를 동시에 만족시킬 수 없다.
4. 다크에서 대비를 확인한다. 본문은 4.5:1 이상.

**확인 방법**

지금 CI 는 라이트 모드로만 찍는다. 그래서 이 문제가 스크린샷에 안 나타났다.
`.github/workflows/ios.yml` 에 다크 모드 촬영을 더해야 고쳤는지 확인할 수 있다.

```
xcrun simctl ui <udid> appearance dark
```

**이 항목은 다크 스크린샷 없이는 고쳤다고 말할 수 없다.** 원격 세션에서는
빌드도 실행도 못 하므로 CI 가 찍어 주는 그림이 유일한 증거다.

## 🔴 2. 계획 화면에서 숫자 키패드를 내릴 수 없어 갇힌다

**증상** (2026-09-06, 빌드 12)

계획 탭에서 금액을 입력하면 숫자 키패드가 올라오는데, 내릴 방법이 없다.
키패드가 탭 바를 덮고 있어서 다른 메뉴로 이동할 수도 없다.

**원인**

`App/Features/Shared/MoneyField.swift` 가 `.keyboardType(.numberPad)` 를 쓴다.
**숫자 키패드에는 return 키가 없다.** 그래서 내리려면 앱이 직접 길을 내줘야 하는데,
`MoneyField` 에는 `완료` 버튼도 포커스 관리도 없다.

`MoneyField` 는 6개 파일 14곳에서 쓰인다. 그중 계획 탭만 **탈출구가 아예 없다.**

| 쓰는 곳 | 어떻게 열리나 | 빠져나갈 수 있나 |
|---|---|---|
| **계획 탭** (`PlanView` 4곳) | 탭 루트 화면 | ❌ **없다.** 키패드가 탭 바를 덮는다 |
| 지난 기록 (3) · 진단 기준 (2) | 밀어 넣은 화면 | △ 키패드 위 내비게이션 바는 눌린다 |
| 자산 편집 (3) · 목돈 (1) · 연금 (1) | 시트 | △ 위쪽 `완료` 는 눌린다 |

주간 점검(`WeeklyReviewView`)만 키보드 툴바를 갖고 있다 — 그래서 거기서는
`1/13 · 변동 없음 · 다음` 이 뜨고 문제가 없었다. 그 부품을 공용으로 못 올린 것이
이 문제의 뿌리다.

**고칠 방향 — 두 층으로 나눈다**

*(1) 버그 (반드시)*

`MoneyField` 안에 `@FocusState` 와 키보드 툴바 `완료` 를 넣는다. 부품 한 곳을
고치면 14곳이 함께 낫는다. 폼에는 `.scrollDismissesKeyboard(.interactively)` 를
더해 스크롤로도 내려가게 한다.

*(2) 워크플로 — 사용자 제안: 읽기 모드 → 편집 → 저장*

제안하신 방향에 동의한다. 다만 **탭 전체를 편집 모드로 감싸는 것보다,
섹션마다 편집 시트를 여는 편**이 낫다고 본다.

| | 탭 전체를 읽기/편집 모드로 | **섹션별 편집 시트** (제안) |
|---|---|---|
| 키패드 함정 | 편집 모드 안에서 여전히 생긴다 | **구조적으로 사라진다.** 시트에는 항상 취소·저장이 위에 뜬다 |
| `저장` 이 진짜인가 | SwiftData 는 `@Bindable` 로 즉시 쓴다. 진짜 저장/취소를 만들려면 autosave 를 끄고 `rollback()` 을 써야 한다 — 앱 전체에 영향 | 시트 범위만 되돌리면 되므로 훨씬 좁다 |
| 계획 탭의 성격 | 편집 모드가 한 겹 늘어난다 | **"지금 내 가정이 무엇인가"를 읽는 화면**이 된다. 앱 성격에 맞다 |
| 기존 코드 | 폼 전체를 다시 짠다 | 목돈·연금이 이미 이 방식이다 (`CashEventEditView`) — 결을 맞추는 일이다 |

읽기 화면에 한눈에 보일 것: 적립 · 수익률·물가 가정 · 기간 · 목표 금액 ·
은퇴 후 생활비 · 연금 · 목돈. 각 묶음 오른쪽에 편집 버튼을 둔다.

> 참고로 iOS 관례상 **설정 성격의 폼에는 편집 모드를 두지 않는다** (설정 앱이 그렇다).
> 그래서 (1)만 고쳐도 갇히는 문제는 사라진다. (2)는 "실수로 계획을 바꿔 놓지
> 않게" 하려는 것이므로, 그 걱정이 실제로 크지 않다면 (1)만으로 끝내도 된다.
> **어느 쪽으로 갈지 정해 주시면 그대로 만든다.**

**확인 방법**

CI 스크린샷은 키보드가 올라온 상태를 찍지 않는다. 계획 화면에서 금액 필드를
탭한 뒤 찍는 컷을 하나 추가해야 `완료` 버튼이 실제로 붙었는지 보인다.
