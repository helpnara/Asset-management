# ADR-0001 · SwiftData + CloudKit private DB를 영속 계층으로 사용

**상태**: 채택 · 2026-09

## 맥락

가족 4인의 자산·계획 데이터를 저장하고, 아이폰과 아이패드 사이에서 동기화해야 합니다.
동시에 [Non-goals](../01-product-spec.md#18-범위-밖-non-goals)에서 자체 서버와 계정
시스템을 배제했습니다. 데이터 양은 작습니다(모델 12종, 레코드 수백~수천 건).

## 결정

**SwiftData**를 영속 계층으로 쓰고, **CloudKit private database** 미러링으로 동기화합니다.
`ModelConfiguration(cloudKitDatabase: .private("iCloud.<bundle-id>"))`.

## 대안

| 대안 | 기각 이유 |
|---|---|
| Core Data + NSPersistentCloudKitContainer | 동일한 동기화 능력에 더 많은 보일러플레이트. SwiftData가 그 위에 있다 |
| GRDB/SQLite + 자체 동기화 | 쿼리는 더 낫지만 동기화를 직접 만들어야 한다. 1인 개발에서 감당 못 함 |
| Realm | 유지보수 방향 불확실, 애플 생태계 통합이 약함 |
| Supabase/Firebase | 서버가 생긴다. 가족 금융 데이터가 제3자를 거친다. 프라이버시 모델이 깨짐 |
| 로컬 전용 + 수동 파일 백업 | 기기 분실 = 전체 손실. 사용자 신뢰를 얻기 어렵다 |

## 결과 (제약과 대응)

CloudKit 미러링을 켜면 스키마에 강한 제약이 걸립니다. **처음부터 지켜야 하며,
나중에 켜려면 스키마를 다시 만들어야 합니다.**

| 제약 | 대응 |
|---|---|
| `@Attribute(.unique)` 사용 불가 | 유일성은 앱 레벨에서 검사. `UUID` id를 직접 관리 |
| 모든 속성에 기본값 또는 옵셔널 필요 | 모든 `@Model` 속성에 기본값을 명시 |
| 모든 관계가 옵셔널이어야 함 | to-one은 `Type?`, to-many는 `[Type]? = []` |
| 필수(non-optional) 관계 표현 불가 | 부모 없는 자식 레코드가 생길 수 있다고 가정하고 방어적으로 조회 |
| 초기 동기화 지연 | 첫 실행 시 "동기화 중" 상태를 화면에 노출 |
| 충돌 해결은 last-writer-wins | 기기 2대 동시 편집은 드물다고 가정. 스냅샷은 날짜 키로 병합 |
| 대용량 바이너리 부적합 | 이미지/첨부는 v1에 넣지 않는다 |

### 검증 과제 (M0)
1. 실기기 2대에서 12개 모델 전체가 정상 동기화되는지
2. iCloud 계정이 없거나 꺼진 상태에서 로컬 전용으로 정상 동작하는지
3. 스키마 마이그레이션이 CloudKit 미러링과 함께 동작하는지

3번이 실패하면 재고합니다. SwiftData 마이그레이션은 이 조합에서 가장 위험한 지점입니다.
