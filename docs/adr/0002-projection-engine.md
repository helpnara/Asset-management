# ADR-0002 · 프로젝션 엔진을 순수 Swift 모듈로 분리

**상태**: 채택 · 2026-09

## 맥락

이 앱의 핵심 가치는 "이대로 가면 은퇴 시점에 얼마"라는 예측입니다.
그 계산은 (a) 틀리면 사용자가 잘못된 재무 결정을 하고, (b) 손으로 검증하기 어렵고,
(c) What-if 슬라이더 때문에 초당 수십 번 호출됩니다.

## 결정

프로젝션·수익률 계산을 **`Core` 로컬 SPM 패키지 안의 순수 Swift 코드**로 만듭니다.
SwiftData, SwiftUI, Foundation의 날짜 포맷터에 의존하지 않고,
`ProjectionInput` → `ProjectionResult` 순수 함수로 정의합니다.

## 대안

| 대안 | 기각 이유 |
|---|---|
| ViewModel 안에서 직접 계산 | 시뮬레이터 없이 테스트 불가. 화면과 얽혀 회귀가 잦아짐 |
| SwiftData 모델의 computed property | 계산이 영속 계층에 묶여 단위 테스트가 느려짐 |
| 서버에서 계산 | 서버를 두지 않기로 함 |

## 설계

### 결정론적 프로젝션
월 단위 스텝, 각 스텝에서 적립 유입 → 목돈 이벤트 → 자산군별 수익 적용 →
(은퇴 후) `생활비 − 연금소득` 인출. 360스텝(30년)이 1ms 미만이어야 합니다.

### 몬테카를로
자산군별 `(μ, σ)`에서 월 수익률을 샘플링해 1,000경로를 돌립니다.

- 자산군 간 상관관계는 v1에서 무시합니다(단순 독립 가정). 상관행렬은 v1.1 후보.
- 난수는 시드 고정 가능한 생성기를 씁니다 → **테스트 재현성**과 같은 입력에 같은 그림.
- `TaskGroup`으로 경로를 병렬 실행하고 백그라운드 actor에서 수행합니다.
- 목표: 1,000경로 × 360스텝 200ms 이내 (M0에서 벤치마크로 검증)

### What-if 성능 전략
슬라이더 드래그 중에는 **결정론적 경로만** 재계산하고(즉시 반응),
손을 떼면 몬테카를로를 돌려 밴드를 채웁니다. 이 분리가 60fps의 조건입니다.

### XIRR
Newton–Raphson으로 풀고, 발산하거나 200회 안에 수렴하지 않으면 이분법으로 폴백합니다.
현금흐름이 모두 같은 부호이거나 1건 이하면 `nil`을 반환합니다(정의되지 않음).

## 결과

- `Core`는 Foundation 외 의존이 없으므로 `swift test`가 수 초 안에 끝납니다.
- 계산 결과를 손계산 기대값과 비교하는 테스트를 쓸 수 있습니다.
- 나중에 macOS 도구나 위젯에서 같은 엔진을 그대로 씁니다.
- 비용: `@Model` 타입 ↔ `Core` 값 타입 매핑 코드가 필요합니다. 이 비용은 받아들입니다.
