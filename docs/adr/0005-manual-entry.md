# ADR-0005 · 자산 평가액은 전부 수동 입력, 주기는 매주 토요일

**상태**: 채택 · 2026-09

## 맥락

이 앱은 자산 관리 도구가 아니라 **노후 준비 현황판**입니다. 목적은 잔고를 정확히 아는 것이
아니라, **계획 대비 실적을 사용자가 체감하는 것**입니다.

기술적으로는 해외 주식·ETF·암호화폐의 시세와 환율을 공개 API로 가져올 수 있습니다.
초기 설계는 그렇게 잡혀 있었습니다(자동 11건 / 수동 7건). 그러나 그 방향은 목적과 어긋납니다.

## 결정

**모든 평가액을 사용자가 직접 입력합니다. 시세·환율을 외부에서 가져오지 않습니다.**
입력 주기는 **매주 토요일**이며, 알림에서 시작해 3분 안에 끝나는 것이 설계 목표입니다.

## 근거

1. **적는 행위가 곧 체감이다.** 숫자가 저절로 채워지면 사용자는 결과를 *보기만* 합니다.
   매주 지난주 값 옆에 새 값을 적으면 "이번 주에 얼마 늘었나"를 손으로 겪습니다.
   이 앱이 팔려는 것이 바로 그 감각입니다.
2. **정확도보다 연속성이 중요하다.** 노후 궤적에서 중요한 것은 소수점이 아니라 20년치 추세입니다.
   주 1회 사용자가 적은 값이면 충분히 정확합니다.
3. **자동화는 리듬을 없앤다.** 자동으로 갱신되면 앱을 열 이유가 사라집니다.
   토요일이라는 고정된 리듬이 이 앱을 살아 있게 합니다.
4. **의존성이 사라진다.** 국내 시세 소스 부재, API 약관, 요금, 예고 없는 차단,
   네트워크 오류 처리, 오프라인 캐시 — 이 전부가 문제 목록에서 사라집니다.
5. **프라이버시가 단순해진다.** 아웃바운드 요청이 하나도 없습니다.
   "개발자 서버로 아무것도 안 보낸다"가 아니라 "아무 데도 안 보낸다"가 됩니다.

## 대안

| 대안 | 기각 이유 |
|---|---|
| 시세 자동 + 나머지 수동 | 원래 설계. 목적(체감)을 훼손하고, 화면에 자동/수동 두 종류가 섞여 복잡해진다 |
| 자동을 기본으로, 수동은 옵션 | 기본값이 곧 제품이다. 대부분 자동을 쓰고 체감은 사라진다 |
| 일 단위 수동 입력 | 매일은 지킬 수 없다. 지키지 못하는 주기는 없는 것과 같다 |
| 월 1회 | 궤적의 점이 너무 성기고, 한 번 놓치면 두 달이 빈다. 리듬이 안 생긴다 |

## 결과

### 사라지는 것
- `Services/Quotes`, `Services/FX` 모듈, `QuoteProviding`·`FXProviding` 프로토콜
- `Holding.lastQuoteMinor` / `lastQuoteAt` 등 시세 캐시 필드
- 네트워크 오류·재시도·요율 제한 처리, API 키 Keychain 저장
- 리스크 "국내 시세 소스 부재"

### 새로 생기는 것 — 그리고 여기에 실패하면 앱이 죽는다
- **알림이 유일한 트리거다.** 권한 거부, 재알림, 시간대 변경을 방어적으로 다뤄야 한다
  (→ [4.5 주간 점검 알림](../04-architecture.md#45-주간-점검-알림)).
- **입력 마찰이 곧 이탈률이다.** 자산 24건 3분이 목표이고, 실측으로 지켜야 한다.
- **끝낸 직후 보상이 있어야 한다.** 점검 완료 화면에서 계획 대비 실적과
  연속 기록 주차를 즉시 보여준다. 수고에 값을 붙이는 자리다.
- **불완전한 기록을 허용해야 한다.** 알림에서 총액 하나만 적어도 그 주가 기록된다.
  완벽한 한 주보다 이어지는 스무 주가 낫다.
- `EntryCadence`(매주 / 월 1회 / 고정)로 매주 물어보는 항목을 최소로 유지한다.

### 다시 볼 조건
자산 항목이 40건을 넘어 3분 안에 끝낼 수 없게 되면, 자동 시세가 아니라
**입력 보조**(지난주 대비 증감률만 입력, 계좌 화면 스크린샷에서 숫자 읽기)를 먼저 검토합니다.
자동 갱신은 마지막 수단이며, 도입하더라도 "적어 넣기"를 기본값으로 유지합니다.

## 후속 (2026-09) — 통화도 하나로 통일한다

한때 통화별 입력과 환율 직접 입력을 만들었다가 **걷어냈습니다.**

사용자가 해외 종목도 이미 원화로 환산해서 적고 있습니다. 그렇다면 앱이 통화를
다룰 이유가 없습니다. 만들어 두면 두 가지가 따라옵니다.

- **환율을 안 넣으면 그 종목이 합계에서 조용히 빠집니다.** 1:1 로 세면 달러가
  원으로 둔갑하므로 빼는 쪽이 옳지만, 애초에 없어도 될 함정입니다
- 환율을 앱이 갱신하면 지난주와 이번주 사이의 증감에 **내가 안 한 변화**가
  섞입니다. 손으로 적는 수고의 값이 사라집니다

그래서 **모든 금액은 원화**입니다. 해외 종목의 평가액 칸에는 원화로 환산한
금액을 적고, 화면이 그렇게 안내합니다. `Money` 는 통화를 들고 다니지만
이 앱은 `.krw` 하나만 씁니다 — 나중에 정말 필요해지면 그때 Core 를 열면 됩니다.
