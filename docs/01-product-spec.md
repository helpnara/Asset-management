# 1. 제품 정의 및 요구사항

## 1.1 한 문장 정의

> **우리 가족 노후 준비 현황판.**
> 매주 토요일 직접 숫자를 적어 넣고, 그 숫자가 계획선 위에 있는지 아래에 있는지를
> 은퇴 시점까지 이어지는 하나의 궤적으로 확인한다.

출발점은 사용자가 이미 손으로 만들어 쓰고 있는 A4 1페이지 계획서입니다
(→ [구조 분석](reference/one-pager-analysis.md)).
**이 앱의 목표는 그 1페이지를 살아 움직이게 만드는 것**입니다.

## 1.2 풀려는 문제

계획 자체는 이미 있습니다. 문제는 계획이 **멈춰 있다**는 것입니다.

| 종이 계획서의 한계 | 결과 |
|---|---|
| 갱신할 계기가 없다 | 고쳐야 한다는 걸 알면서도 계기가 없어서 몇 달을 넘긴다. |
| "만약에"를 못 해본다 | 월 50만원 더 넣으면 은퇴 자산이 얼마나 달라지는지 알 수 없다. |
| 계획과 실제를 겹쳐 볼 수 없다 | 3년 지난 지금 계획대로 가고 있는지 확인이 안 된다. |
| 원칙 위반을 사람이 찾아야 한다 | "개별주 4% 상한"을 넘었는지 매번 손으로 계산한다. |
| 기한을 놓친다 | 증여 신고 기한, ISA 만기, 연금저축 한도 재조정 시점. |
| 갱신하려면 처음부터 다시 만든다 | 그래서 분기 1회조차 지키기 어렵다. |

## 1.3 대상 사용자

가족 재무를 실질적으로 설계·관리하는 한 사람. 이미 자기만의 원칙과 계획이 있고,
그것을 유지·점검하는 데 드는 수작업을 줄이고 싶어 합니다.
투자 초보를 가르치는 앱이 아니라, **이미 계획이 있는 사람의 운영 도구**입니다.

## 1.4 핵심 가치 제안

1. **직접 적어 넣기** — 자동으로 채워 주지 않는다. 매주 손으로 적는 행위 자체가
   계획 대비 실적을 몸으로 느끼게 하는 장치다. (→ [ADR-0005](adr/0005-manual-entry.md))
2. **하나의 궤적** — 과거 실제 기록과 미래 예측이 같은 축에서 끊김 없이 이어진다.
3. **구성원별 + 가구 합산** — 아빠·엄마·아들·딸 각각의 궤적과 가족 총합을 함께 본다.
4. **원칙이 스스로 감시한다** — 비중 상한, 지역 배분, 비상금 하한, 세적 제약을 앱이 검사한다.
5. **즉각적인 What-if** — 적립액·은퇴 나이·수익률을 움직이면 궤적이 실시간으로 반응한다.
6. **서버 없음** — 가족 금융 데이터가 개발자 서버를 거치지 않는다. 기기와 본인 iCloud에만 있다.

## 1.5 중심 화면

설계의 모든 판단은 이 두 장을 기준으로 내립니다.

### (1) 현황판 — 1페이지의 재현

```
┌──────────────────────────────────────────────┐
│ 우리 가족 노후자금 준비    2026.08 · 이사 후 │
│                                              │
│           3억 273만원        ▲ 이번 달 +412만 │
│                                              │
│ ●───●───○───○───○───○───○───◉               │  ← 로드맵 타임라인
│ 23  26  29  31  35  38  41  49              │
│    지금            일하지         목표       │
│                    않아도         59.1억     │
│                                              │
│ ┌──── 순자산 궤적 ─────────────────────────┐ │
│ │                              ▒▒▒▒▒▒░░░░  │ │  ← 과거 실선 + 미래 밴드
│ │                      ▒▒▒▒▒▒▒░            │ │
│ │  ●──●──●───┊─ ─ ─ ─ ─                    │ │
│ │            오늘                          │ │
│ └──────────────────────────────────────────┘ │
│                                              │
│ ⚠︎ 개별주 비중 4.6% — 상한 4% 초과            │  ← 원칙 위반 경고
│ ⏰ 증여 신고 기한 2026.12.31 (117일 남음)     │  ← 기한 임박
│                                              │
│ [아빠 2.5억] [엄마 200만] [아들 3,233만] ... │  ← 구성원 카드
```

- **왼쪽(과거)** 은 매일 저장되는 실제 스냅샷입니다. 사실입니다.
- **오른쪽(미래)** 은 가정에 기반한 예측입니다. 점선·반투명 밴드로 명확히 구분해
  사실과 추정을 절대 섞어 보이지 않게 합니다.
- 두 영역이 **같은 Y축, 같은 선**으로 이어지는 것이 이 앱의 핵심 경험입니다.

### (2) 구성원 상세 — 계속 입력하는 화면

종목별 금액을 이어서 고쳐 쓸 수 있어야 합니다. 월 1회 갱신 루틴이
**2분 안에** 끝나지 않으면 앱은 버려집니다.

## 1.6 핵심 시나리오

우선순위 순서이며, 이 순서가 곧 개발 순서입니다.

### S1. 주간 점검 (매주 토요일, 이 앱의 심장)
토요일 오전 9시 알림 → 탭하면 바로 입력 화면. 보유 자산을 위에서 아래로 훑으며
평가액을 적어 넣는다. 다 넣으면 **점검 완료 화면**이 이번 주 변화와
**계획 대비 실적**을 즉시 보여준다. 이 왕복이 앱의 전부다.

알림에서 총액 하나만 먼저 적고 넘어갈 수도 있다. 궤적의 점은 남고,
구성원·종목별 분해는 다음 점검 때 채우면 그 주로 소급 배분된다.
**한 주도 거르지 않게 만드는 것**이 설계 목표다 — 연속 기록 주차를 표시한다.

### S2. 현황 확인 (수시)
앱을 열면 1페이지 현황판이 즉시 보인다. 마지막 점검 값으로 그리고,
예측만 백그라운드로 다시 계산한다. 로딩 스피너를 보여주지 않는다.

### S3. 초기 설정 (온보딩, 1회)
구성원 → 계좌·보유 자산 → 월 적립 → 연금·목돈 이벤트 → 원칙 → 유의사항.
한 번에 다 채우게 하지 않는다. **구성원 1명 + 자산 1개만 넣어도 즉시 궤적이 그려지고**,
빈 항목은 현황판에 "추가하면 예측이 정확해집니다" 카드로 남는다.
기존 스프레드시트가 있으면 CSV로 가져온다.

### S4. What-if 시뮬레이션 (월 1회, 이 앱의 재미)
슬라이더(월 적립액 / 은퇴 나이 / 기대수익률 / 은퇴 후 월 지출)를 움직이면
궤적과 요약 문장이 60fps로 따라온다. 마음에 드는 조합은 시나리오로 저장하고
기본 시나리오와 겹쳐 비교한다.

### S5. 원칙 점검 (주간 점검에 포함)
입력이 끝나면 원칙 위반 여부와 한도 사용률이 자동으로 계산된다.
기한 임박 항목도 같은 자리에서 처리한다. 종이 계획서가 못 하던 일이 바로 이것이다.

### S6. 계획서 내보내기 (분기~반기 1회)
현재 상태로 1페이지 PDF/이미지를 생성해 배우자와 공유하거나 인쇄한다.

### S7. 연금 점검 (연 1회)
국민연금·퇴직연금·개인연금의 예상 수령액을 갱신한다.
연금은 노후 현금흐름의 큰 축이므로 별도 화면으로 다룬다.

## 1.7 기능 요구사항

### v1 (첫 출시)

**가족 · 구성원**
- 구성원 CRUD — 이름/호칭, 생년월, 세적(한국/미국/이중), 은퇴 목표 나이, 표시 색
- 구성원별 자산 합계·월 적립·성장 궤적, 가구 합산

**자산 입력**
- 계좌 CRUD — 소유자, 기관, 계좌 종류(일반/ISA/연금저축/IRP/퇴직연금/보험/예금/보증금/대출), 통화
- 보유 자산 CRUD — 종목명, 자산군, 상장 국가, 통화, 평가액
- **보유 상태 태그** — 적립중 / 동결 / 신규 / 정리완료
- **입력 주기 태그** — 매주 / 월 1회 / 고정(입력 대상에서 제외)
- 거래 CRUD (선택 기능) — 매수/매도/입금/출금/배당/이자/수수료/세금
- 다중 통화 → 기준 통화 환산 (환율도 사용자가 입력하거나 기본값 사용)

**주간 점검**
- **토요일 알림** — 시각 설정 가능, 미입력 시 일요일 1회 재알림
- 알림 확장 시 **총액 빠른 입력** (전체 목록을 열지 않고 점 하나만 남기기)
- **연속 입력 화면** — 구성원별 그룹, 지난주 값·증감 실시간 표시, 키패드 유지
- **점검 완료 화면** — 이번 주 변화, 계획 대비 실적, 최근 12주 실적 대 계획, 구성원별 증감
- **연속 기록 주차** 표시
- 주간 순자산 스냅샷 기록 (점검 1회 = 스냅샷 1건)

**계획**
- 적립 계획 — 구성원별 월 금액, 대상 계좌/종목 배분, **본인 부담 / 회사 매칭 구분**, 연 증가율, 종료 시점
- 미래 소득 — 국민연금/퇴직연금/개인연금/임대소득 등, 수령 시작 나이, 월 금액, 물가연동 여부
- **목돈 이벤트** — 특정 시점의 큰 유입·유출(퇴직금, 보증금 전환, 주택 구입)과 배치 대상
- 마일스톤 — 연도 + 사용자 라벨, 자동 판정 가능한 교차점(수익 > 적립금 등) 자동 표시
- 은퇴 후 목표 생활비(실질가치 기준)
- 가정 — 자산군별 기대수익률·변동성, 인플레이션율

**예측**
- 결정론적 프로젝션 (적립 + 목돈 + 수익 + 인플레이션 + 연금 + 인출)
- 몬테카를로 시뮬레이션 → 신뢰구간 밴드, 목표 달성 확률, 자산 고갈 나이
- 실질가치(오늘 돈 기준) / 명목가치 토글
- What-if 슬라이더, 시나리오 저장·비교
- 계획선 대비 실제선 편차

**점검**
- **운용 원칙 CRUD + 자동 점검** — 개별 종목 비중 상한, 자산군 상한, 지역 배분,
  현금성 자산 하한, 동결 종목 신규 매수 감지
- **세적 제약 경고** — 미국 세적 구성원 계좌에 한국 상장 ETF(PFIC) 추가 시 경고
- **한도 게이지** — 연금저축 연 600만, IRP, ISA 총 한도 대비 사용률
- **기한 있는 유의사항** — 체크리스트 + 로컬 알림(증여 신고, 만기, 정기 점검)

**공통**
- 1페이지 PDF/이미지 내보내기 및 공유
- Face ID 앱 잠금, 금액 가리기 모드
- CSV 가져오기/내보내기
- iCloud 동기화 (같은 Apple 계정의 다른 기기)

### v1.1 이후 (확정 순서 아님)
- 홈 화면·잠금 화면 위젯 (총자산, 목표 달성률, 은퇴까지 남은 기간)
- 배우자와 실시간 공유 (CloudKit shared database → [ADR-0004](adr/0004-family-sharing.md))
- 리밸런싱 제안 (목표 배분까지 자산군별 매수·매도 금액)
- 국민연금 예상 수령액 추정기
- 세금 반영 (금융소득종합과세, 연금 수령 세율, 미국 세적자 신고 항목 정리)

- iPad·Mac 레이아웃 (1페이지 원본 비율 그대로)

## 1.8 범위 밖 (Non-goals)

| 항목 | 이유 |
|---|---|
| 가계부 / 지출 카테고리 분석 | 다른 제품이다. 지출은 "월 적립액"과 "은퇴 후 생활비" 두 숫자로만 모델링한다. |
| 금융기관 자동 연동 (마이데이터) | 신용정보법상 본인신용정보관리업 허가가 필요하다. 개인 개발자가 할 수 없다. |
| 웹 스크래핑 방식 잔고 수집 | 기관 약관 위반이며 사용자 자격증명을 앱이 다루게 된다. |
| **시세 자동 갱신** | 기술적으로는 가능하지만 **의도적으로 하지 않는다.** 직접 적어 넣는 행위가 계획 대비 실적을 체감하게 하는 장치다. 자동으로 채우면 숫자를 보기만 하고 느끼지 않는다. (→ [ADR-0005](adr/0005-manual-entry.md)) |
| 실제 주문/거래 실행 | 투자중개업 영역이다. |
| 투자 상품 추천 | 투자자문업 규제 대상이다. 앱은 **사용자가 등록한 원칙과 가정을 계산해 줄 뿐**이며 화면에 이를 명시한다. |
| 세무 신고 대행·세액 확정 계산 | 세법 해석 책임을 질 수 없다. 기한 알림과 참고 링크까지만 한다. |
| 계정 시스템 / 자체 서버 | 프라이버시 모델이 깨진다. 가족 공유는 CloudKit으로 해결한다. |
| 광고 · 추적 SDK | 가족 금융 데이터를 다루는 앱에 넣지 않는다. |

> **모든 입력이 수동이라는 점은 약점이 아니라 이 제품의 선택입니다.** 대신
> (a) 주간 루틴이 몇 분 안에 끝나야 하고, (b) 끝낸 직후 보상(계획 대비 실적)이
> 즉시 보여야 하며, (c) 알림이 그 주에 반드시 도달해야 합니다.
> 이 세 가지가 부가 기능이 아니라 핵심 기능입니다.

## 1.9 비기능 요구사항

- **입력 속도** — 자산 24건 주간 점검을 **3분 이내**에 끝낼 수 있어야 한다. 실측으로 검증한다.
- **성능** — 현황판 첫 프레임 400ms 이내(자산 300건 기준).
  몬테카를로 1,000 경로 × 30년은 백그라운드에서 200ms 이내
  (→ [ADR-0002](adr/0002-projection-engine.md)).
- **정확성** — 금액·수량 계산에서 부동소수점 오차가 누적되지 않아야 한다
  (→ [ADR-0003](adr/0003-money-representation.md)).
- **오프라인** — 네트워크를 전혀 쓰지 않는다(iCloud 동기화 제외). 기내에서도 완전히 동작한다.
- **프라이버시** — iCloud 동기화 외에 어떤 아웃바운드 요청도 하지 않는다.
  개발자가 운영하는 서버가 존재하지 않는다.
- **정직성** — 예측은 항상 가정과 함께 표시한다. 모든 예측 화면에
  "입력한 가정에 따른 계산이며 미래 수익을 보장하지 않습니다" 고지를 둔다.
- **접근성** — Dynamic Type, VoiceOver. 차트는 데이터 요약을 음성으로 제공한다.
- **국제화** — v1은 한국어. 문자열은 처음부터 String Catalog로 분리한다.
