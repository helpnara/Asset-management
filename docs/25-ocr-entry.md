# 25. 증권사 화면 캡처로 주간 점검 채우기 — J3 검토 (2026-11-20)

> 11-20 사용자: *"제이 쓰리 … 증권사별로 앱을 찍어가지고 … 핸드폰에 있는 OCR 인식해 가지고 … 실패하거나 올바르게 넣지 못할 확률이 1% 정도 될지 예상해 볼 수 있을까 … 개인적으로 이미지를 올리는 거기 때문에 … 외부로 나가지 않고 보안 측면에서도 괜찮을 거 같거든 … 시뮬레이션을 1번 해 봐"*
> 이어서: *"계좌별로 캡처 화면을 여러 개를 쭉 찍고 나서 그거를 한 번에 올리면 … OCR … 정보를 추출해서 … 지금 앱에 등록되어 있는 계좌 … 화면에다가 등록하는 거야 그리고 없다라고 하면 그 부분을 입력하라고 표시하는 방식"*

배경은 [17 F 11-20 브레인스토밍](17-after-launch.md) J3.

## 보안 — 밖으로 나가는 것이 없다

| | |
|---|---|
| 글자 인식 | Apple **Vision** (`VNRecognizeTextRequest`) — **기기 안에서** 돈다. 네트워크를 쓰지 않는다. iOS 사진 앱의 "텍스트 인식 표시(Live Text)" 와 같은 엔진 |
| 사진 고르기 | `PhotosPicker` — 앱 밖(시스템)에서 고른 사진만 앱에 건네진다. **사진 보관함 권한을 묻지 않는다**, 개인정보 명세도 그대로 |
| 그림 보관 | 읽고 나면 버린다. 저장소 · iCloud 에 남기지 않는다 — 남는 것은 사람이 `완료` 를 누른 **금액** 뿐(지금 손으로 적는 것과 같다) |
| ADR-0005 | "시세 · 환율을 밖에서 가져오지 않는다" 와 부딪치지 않는다 — 숫자는 여전히 **사람이 본 화면**에서 오고, 사람이 확인한다 |

## 시뮬레이션 (11-20) — `Tools/ocr-sim`

1. **가상 캡처 9장 · 종목 71개** — 증권사 보유 화면에 흔한 배치 넷(목록형 · 카드형 · 표형 · 펀드형) + 다크 모드. 이름 · 금액은 모두 지어낸 것, 실제 증권사 디자인은 흉내 내지 않았다. 긴 이름 `…` 잘림 · 매입금액 · 평가손익 · 수익률 · 수량 같은 헷갈리는 숫자를 일부러 넣었다.
2. **macOS 러너(Xcode 27 · macOS 27)에서 Apple Vision 으로 읽기** — `ocr.swift`.
3. **채점** — `score.py`: 화면 배치를 미리 알지 않고 ① 이름 줄 찾기 ② 그 아래에서 평가금액 고르기(`평가금액` 이름표가 있으면 그 줄, 없으면 가장 큰 글씨) ③ 등록된 종목 이름과 맞추기(잘린 이름은 앞부분) ④ **계좌 총액 = 읽은 금액의 합** 검산.

### 결과

| | |
|---|---|
| **정밀 인식(`.accurate`) — 러너에서 안 돈다** | `CRImageReaderError.unknownError` · `AppleM2ScalerParavirtDriver` 없음. GitHub macOS 러너는 가상 머신이라 전용 하드웨어가 없다. 그림을 줄여 넘기기 · 새 Swift API(`RecognizeTextRequest`) 도 같은 오류(탐침 5 · 6 · 7) |
| 빠른 인식(`.fast`)만 돌았다 | 빠른 인식은 **한글을 읽지 못한다** — `가나전자` → `ty7FJOH`. 그래서 이름 맞추기가 거의 다 실패, 전체 **15.5%(11/71)** — **iPhone 의 정밀 인식 성능이 아니다** |
| 숫자는 그 약한 모드에서도 정확 | **계좌 총액 9/9**, 목록형 첫 화면 금액 **9/9** (`원` 만 `i` 로 읽음 — 숫자에는 영향 없음) |
| **검산** | 틀리거나 빠진 60건을 **60/60** 잡았다 — 합이 총액과 안 맞으면 그 계좌는 "확인 필요" 로 |

### 1% 질문에 대한 답

- **러너로는 iPhone 의 실제 오류율을 잴 수 없었다.** 이 숫자는 기기에서 재야 한다(아래 다음 단계).
- 그래도 설계로 정할 수 있는 것: **"틀린 값이 조용히 들어가는 확률"** 은 검산으로 사실상 0 에 가깝게 만들 수 있다. 계좌 총액과 합이 맞으려면 틀린 값 둘이 정확히 서로를 메워야 한다. 합이 안 맞으면 그 계좌는 자동으로 넣지 않고 사람에게 묻는다.
- 남는 것은 **"자동으로 못 채워 손으로 적는 칸"** 이다. 깨끗한 캡처(사진이 아니라 화면 캡처)에서 정밀 인식의 숫자 읽기는 매우 정확한 편이라, 주된 원인은 OCR 보다 **이름 맞추기**(증권사 이름 ↔ 앱에 적은 이름)와 **화면 배치**다. 처음 한 번 짝을 지어 두면(아래 설계) 다음 주부터는 줄어든다.

## 사용자 제안 흐름 — 검토

> 계좌별로 여러 장 캡처 → 한 번에 올리기 → 앱이 등록된 계좌 · 종목을 찾아 채우기 → 못 찾은 것은 "입력하세요" 로 표시

| 단계 | 앱이 할 일 | 걸리는 것 · 정할 것 |
|---|---|---|
| 1. 여러 장 고르기 | `PhotosPicker` 여러 장 선택. 주간 점검 화면 위 `캡처로 채우기` | — |
| 2. 장마다 읽기 | Vision 정밀 인식, 기기 안. 장당 1초 안팎 예상 | 오래된 기기에서는 느릴 수 있다 |
| 3. 어느 계좌인가 | 맨 위 계좌 줄(종류 · 끝자리) · 총액을 읽는다. **처음 한 번은 사람이 고른다** → 기억 | 계좌에 "캡처 표시" 를 기억할 칸 — 스키마 1칸(CloudKit 재배포) 또는 기기 안(UserDefaults) |
| 4. 같은 계좌 여러 장 | 스크롤해 찍은 장끼리 겹친 줄은 이름으로 하나로 | 계좌 총액은 첫 장에만 있다 — 검산은 계좌 단위로 |
| 5. 종목 맞추기 | 증권사 이름 ↔ 앱 종목 이름. **처음 한 번 짝지어 기억**(다음부터 자동) | 짝을 기억할 칸 — 위와 같은 선택. 앱 종목 이름을 증권사 이름으로 바꾸면 기억 없이도 맞는다 |
| 6. 검산 | 계좌마다 읽은 합 = 화면 총액? 맞으면 초록 `확인됨`, 아니면 노랑 `확인 필요` | 화면에 총액이 없는 증권사 화면 — 그때는 지난주 대비(B2 크게 바뀐 항목)로만 |
| 7. 결과 보여 주기 | 주간 점검 목록에 **값을 미리 채워** 보여 준다(아직 저장 안 함). 못 찾은 종목 · 확인 필요 계좌는 표시 | 사람이 훑어보고 `완료` — 지금의 끝내기 그대로(219 A · 220) |
| 8. 없는 것 | 앱에 없는 종목이 캡처에 있으면 "새 종목?" 으로만 알리고 만들지 않는다. 캡처에 없는 앱 종목은 "이번 주 캡처에 없음 — 직접 적기" | — |

**판단** — 흐름 자체는 맞다. 가장 큰 위험(틀린 값이 조용히 들어감)은 **검산 + 미리 채우기 + 사람 확인**으로 막힌다. 남은 질문은 **실제 증권사 화면에서 정밀 인식이 얼마나 읽느냐** 하나다.

## 다음 단계 — 기기에서 재기 (러너로는 못 잰다)

1. **빌드 없이 지금 할 수 있는 것 (권함)** — 쓰는 증권사 앱의 보유 종목 화면을 캡처 → 사진 앱에서 그 캡처를 열고 오른쪽 아래 **텍스트 인식 단추(Live Text)** → 글자를 길게 눌러 `모두 선택` → `복사` → 메모 앱에 붙여 보기. 같은 엔진이라, 종목 이름 · 평가금액이 화면과 똑같이 나오는지 보면 된다. **실제 금액이라 결과를 보내 주실 필요는 없고**, "몇 줄 중 몇 줄이 정확했다" 만 알려 주시면 된다.
2. 그다음 — TestFlight 에 **숨은 시험 화면**(캡처를 골라 읽은 결과와 검산만 보여 주고 아무것도 저장하지 않는 화면)을 넣어, 위 2~6 단계를 실제 화면으로 잰다. 여기서 "검산 통과 계좌 비율 · 손으로 적어야 하는 칸 수" 를 숫자로 얻는다.
3. 숫자가 좋으면 7~8 단계까지 만들어 2.0 후보로.

## 11-20 기기 확인 — 텍스트 인식(Live Text)

사용자: *"Live Photo로 글자 추출 해 보니까 인식률은 거의 100%에 근접하는 거 같애"* — 실제 증권사 화면 캡처를 사진 앱의 텍스트 인식으로 뽑아 본 결과. 정밀 인식 엔진의 **글자 읽기**는 문제가 아니다.
남은 것은 **글자 → 숫자 고르기**(배치마다 평가금액이 어느 숫자인가) · **이름 맞추기** · **검산 통과 비율** — 앞 표의 3~6 단계. 다음 단계 2(TestFlight 시험 화면, 저장 안 함)로 실제 화면에서 잰다.

## 11-20 시험 화면 착수 (08 221번)

사용자: *"착수하자. 시험 화면 만들어줘"*. 읽기 규칙을 `Core/CaptureParser` 로 옮기고(테스트 6), 가상 캡처의 글자를 **완벽히 읽었다고 치고** 규칙만 시험 — **71/71 · 검산 9/9**(`ideal_lines.mjs` → `score.py ideal.jsonl`). 앱은 `더보기 → 실험 → 캡처 읽기 시험`. 이 화면으로 실제 증권사 화면에서 잴 것:

| 잴 것 | 화면에서 보는 곳 |
|---|---|
| 평가금액을 맞게 골랐나 | 종목 줄 오른쪽 금액 ↔ 증권사 화면 |
| 검산 통과 비율 | 맨 위 `검산 통과 a / b장` |
| 이름 짝 비율 | 맨 위 `앱 종목과 짝 c / n` · 줄마다 `→ 앱 종목` 또는 `앱 종목과 짝 없음` |
| 못 읽은 배치 | `확인 필요` · `총액 못 찾음` 장의 `읽은 글자` 펼치기 |
